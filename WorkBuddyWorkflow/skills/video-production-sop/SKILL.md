# 代码逐帧渲染视频 · 通用生产流程（video-production-sop）

## 何时使用

- 制作或修改**画面由代码按时间计算**的短视频：知识科普、数据解说、产品演示、动画短片。
- 竖版（9:16）与横版（16:9）都适用；本文的具体数值来自竖版参考实现，换画幅只需改参数。
- 排查这类管线的问题：文字消失、慢放掉帧、音画错位、生成 OOM、成片"卡住"。
- 不适用：真人口播、纯剪辑（非代码渲染）、复杂三维。

> 完整方法论（七参数决策表、迁移清单、判据来源）见仓库 `WorkBuddyWorkflow/视频制作通用流程.md`；
> 本文是给执行用的浓缩版，判据与硬规则优先。

## 核心思想

1. **逐帧确定性渲染**：所有动画是时间 `lt` 的纯函数（`render(lt)` / `FNS.sN(lt,t,el)`），任意一帧可复现、可定位、可对比。
2. **三层分离**：素材层（AI/实拍/渲染）+ 覆盖层（文字图形，透明）+ 音轨，各自生成后一次性合成。
3. **量化质检**：不靠"看着还行"，靠判据（最长静止 ≤3s、时长误差 ≤0.06s、关键帧像素特征）。

## 时间模型（一切对齐的基准）

| 项 | 规则 |
|---|---|
| 节奏基准 | 有 BGM 用 BPM（每拍 = 60/BPM）；无 BGM 用固定镜头时长 |
| 分镜时长 | `拍数 × 每拍` —— 唯一公式，素材层与覆盖层都必须服从 |
| 全片 | **总拍数守恒**：Σ拍数 × 每拍 = 成片时长 = 音轨时长 |
| 帧率 | 全片统一（参考实现 24fps）；素材层与覆盖层必须一致 |
| BGM | 合成时**不加 `-shortest`**（会裁尾帧） |

参考实现实例：BPM 112.3 → 每拍 0.53406s；256 拍 = 136.719s；14 镜。**数值是示例，不是规范。**


**三条铁律**
1. 改 `timeline.json` 后必须重生成 `timeline.js`（浏览器只读 js）。
2. **拍数变了的镜头必须重建 base 分段**，否则旧分段与新时间轴错位。
3. 覆盖层按全局 `t` 驱动，base 按拼接顺序对齐——两边都只认 timeline，不要各自写死时间。

## 八步流程

> 命令与路径是**参考实现**（仓库 `WorkBuddyWorkflow/src|scripts`）的写法。换项目/换画幅时替换成你的路径，
> 步骤顺序与判据不变。

1. **定节奏**：改 `src/timeline.json` → `python scripts/build_timeline.py`，核对总拍数与每镜时长。
2. **概念首帧**：`src/cN.html` → `node scripts/concept_render.js <N>` → `out/ai/concepts/cN.png`（704×1280）。
   - **媒介按题材选**：抽象机制/图表/数据用 SVG·HTML（精确可控）；实景/解剖/光影/氛围用**图像生成**（材质与景深 SVG 做不出来）。选错媒介，"粗糙"是必然的，不是细节问题。
   - 抽象感受要落在一个实物上（"闭眼后的黑暗"→全黑空画面；"闭眼特写+眼睑透光"才成立）；解剖类必须给**视角+部位名**。
   - 批量出完先拼一张总览图看风格一致性，比逐张 review 快一个数量级。
3. **生成底板**：提示词写进 `scripts/wan22.py` 的 `SCENES[N]`（四查：细节充分/契合功能/同向概念帧/区别于他镜），`python scripts/gen_one.py <N> <seed> 121`。
   - **必带运动**：不写 "completely still"；写慢眨眼、呼吸、光效明灭、极缓推近。静止素材会触发节奏缺陷。
4. **建底板**：`python scripts/build_base.py 3,7,13`（只重建改动镜头）。配置项：`LOOK` 调色/特效、`TRIM/TRIM_END` 裁头尾、`PARTS_TIMED` 分段定速、`GEO` 改构图、慢放 `setpts+minterpolate`。
5. **做覆盖层**：在 `src/index.html` 的 `<section id=sN>` 加 `data-t/data-anim/data-d`；需要逐帧逻辑写 `FNS.sN(lt,t,el)`；卡点光效配 `FLASH[N]`。
6. **单镜预览（每次改画面必做）**：`node scripts/scene_preview.js s6 5 --base`，秒级出图，查排版/时序/构图 + JS 报错。
7. **合成**：`node scripts/composite.js 24`（Puppeteer 逐帧截图 → ffmpeg 叠加 base+BGM）。
8. **质检交付**：`python scripts/qc_rhythm.py` 必过 + `ffprobe` 音画时长一致 + 关键帧像素抽检 + 音频电平（mean≈-15dB）。

## 七条硬规则（违反必出 bug）

**渲染五条**
1. **禁止 CSS transition / keyframes**——逐帧 seek 会抖，动画全部由 `render(lt)` 计算。
2. **禁止 `Math.random()`**——每帧重算会跳，用确定性 `rng(seed)`。
3. **禁止 `background-clip:text`**——无头 Chrome 合成层丢渐变填充（字变透明）；用纯色 + text-shadow 光晕。
4. **带样式的原子标签不可拆字**（`tx-grad/tx-mark/tx-serif` 等），拆了样式丢失、字消失。
5. **慢放素材要与动画同步**：视频放慢 K 倍时，在 FNS 首行 `lt/=K` 把本地时间压回设计时刻表（保证动作落点仍等于画面事件）。

**工程两条**
6. **单镜样式必须 `#sN` 限定**——改 `.txt/.h1` 这类全局类会移动全片所有镜头。判断：这次是"这一镜特殊"还是"全片都该变"。
7. **绝对定位块必须算垂直占位**——同 section 多个 absolute 块的 top/bottom 各写各的，重叠在缩略图上看不出来。排完版列一遍 `top` 与 `top+高度` 确认无交叠；文字块高度随内容变，别只看首行。

## 三道质检闸门

| 闸门 | 工具 | 判据 | 时机 |
|---|---|---|---|
| ① 单镜 | `scene_preview.js` | 无 JS 报错；排版不压主体；**文字与底板亮部对比度**；时序 | 每次改画面 |
| ② 节奏 | `qc_rhythm.py` | **每镜最长静止 ≤3.0s**；静止占比>45% 提示 | 合成后 |
| ③ 成片 | ffprobe + 像素统计 | 时长严丝合缝；关键帧特征（如落点、文字带亮度、光效搏动）；音频电平 | 交付前 |

### 闸门①之前：先确认预览工具可信

**这是最容易骗人的一环。** 预览若没真正叠上底板，看到的"干净画面"是假的——排版完美，成片里文字全压在亮背景上。

- **自检法**：挑一个你确定应该出现的底板特征（柱子/人脸/星空），预览里必须看得见。看不见 = 叠加链路断了，先修工具。
- 预览脚本里任何"为了好看"设的底色/背景都会破坏透明叠加，一律不要加。
- 曾踩：`scene_preview.js` 给 body 设不透明底色，连续几轮预览都说"没问题"，合成才暴露 s8 文字压柱。

### 覆盖层框架：新片新建，别抄旧片

旧片的 `render` 与它自己的场景结构强耦合（硬编码 `.s3head`、`.s7head` 这类按镜号起的类名），照抄会把旧片构图假设一起带进来。**可复用的是驱动模型，不是代码**：

- **元素级声明式驱动**：`data-t`（本镜相对秒）+ `data-anim`（rise/fall/scale/pop/left/right/blur/fade）+ `data-d`（时长），逐帧由统一 `render(t)` 计算
- 只有声明式表达不了的特殊效果才写 `FNS.sN(lt,t,el)`
- 效果：九成镜头只改 HTML 属性不碰 JS；节奏调整集中在一处，不会漏镜头

### 透明模式：URL 参数只是开关，样式还得自己加

`?ov=1` 是**信号不是行为**，样式仍要在脚本里给 `html`/`body` 加透明类（如 `.ov{background:transparent}`）。漏了这步底色仍是 `#000`，截图带黑底，叠底板时把素材**整帧盖掉**——表现是"预览只有文字、背景全黑"。

**预览干等超时先查依赖**：预览靠 `window.TIMELINE` 就绪后置位 `__ready` 再截图。忘引时间轴脚本 → `TIMELINE` 空 → `__ready` 永不置位 → 白等超时。超时先看脚本加载与就绪标志，别先怀疑动画代码。

### 文字可读性：自动判据测不到的第四道关

文字与素材层分开开发，"文字压亮部"只有合成后才暴露，而帧间能量/时长/电平都不管对比度。
→ 设计文字位置时就看底板亮度；素材有亮区（人脸/发光物/窗帘）时，文字**加底衬或错位**，二选一。

### 判据在测什么（决定你能怎么改）

闸门②的静止占比 = **全画面帧间平均绝对差**（下采样 240×428 灰度），所以：
- 小元素推不动它：r=8 光点贡献 <0.0005，阈值 0.0012。加四段尾迹只降 2 个百分点。
- 要推动它必须**大面积或高对比**：大面积低幅呼吸光 > 小光点；长线条扫过（时钟指针）最强。
- **通过 ≠ 观感好**（花哨廉价的运动也能过）；**不通过 ≠ 难看**（收尾定格本该静）。

**正确用法**：用它发现漏掉的死角，不是刷分。发现后先问"为什么这么久没变化"——答案通常是**镜头太长**或**素材本身静态**，要改结构而非加特效。

## 踩坑速查（症状 → 根因 → 规则）

| 症状 | 根因 | 规则 |
|---|---|---|
| 字消失/透明 | `background-clip:text` 丢填充 | 纯色 + 光晕 |
| 慢放掉帧/幻灯片 | `fps` 复制帧 | `setpts` + `minterpolate=mi_mode=mci` |
| 拼接后总长被压缩 | 多段 xfade 塞一条 filtergraph，offset 错位 | 分步 concat，每步校验 |
| `-ss/-to` 时长不对 | 放在 `-i` 之后被当输出限制 | 输入侧裁剪，放 `-i` 前 |
| 生成 OOM（node 10） | 外部进程瞬时占显存，门控只看利用率% | 空闲显存硬门槛（≥9GB） |
| 误判"两个 ComfyUI 抢端口" | venv 与 uv python 是父子进程=同一服务 | 查 ParentProcessId |
| 后台任务莫名消失 | shell 里加 `&` 随 shell 退出被连坐 | 用托管后台任务 |
| 成片下部很黑 | `.ov-scrim` 覆盖层压暗渐变，设计如此 | 勿与未加 scrim 的底板对比误判 |
| 慢推加了没效果 | 镜头级速率（5%/1.5s）拉长到整镜慢 20 倍 | 镜头级用，或换素材 |
| 周期性光效"无差异" | 跨拍抽帧被底板慢漂移混淆 | 抽**同拍相邻帧** |
| 单镜时长错位 | 改了 beats 却复用旧分段 | 改拍数必须重建该镜 |
| 预览"排版完美"，成片文字压背景 | 预览脚本给 body 设不透明底色，底板被盖掉 | 预览保持透明 + 已知特征自检 |
| 透明模式预览只有文字、背景全黑 | 只加 `?ov=1` 参数，没在脚本里给 html/body 加透明类，底色仍 `#000` | 参数只是开关，样式必须同时改 |
| 单镜预览干等超时、无报错 | 没引时间轴脚本 → `window.TIMELINE` 空 → `__ready` 永不置位 | 超时先查脚本加载与就绪标志 |
| 队列十几小时无产出，任务仍占 running | 执行线程已挂（`/history` 空、`interrupt` 无效），不是排队慢 | 三判据确认后重启服务；会堵死整条共享队列 |
| 覆盖层照抄旧片，改一镜要动一堆硬编码类名 | 旧片 render 与旧场景结构强耦合 | 只复用驱动模型（`data-*` 声明式），代码新建 |
| 文字压亮部看不清，自动判据全过 | 对比度不在任何判据里 | 排版前看底板亮度；亮区加底衬/错位 |
| 加一堆小动效，静止占比只降 2% | 判据算全画面平均差，小元素贡献 <0.0005 | 用大面积/高对比；或改镜头长度 |
| 改一处样式全片移位 | 动了全局类 | 单镜改动带 `#sN` |
| 两块叠一起，缩略图看不出 | absolute 块各写 top/bottom，没算占位 | 排完版做占位核算 |
| 17s 镜头怎么加动效都闷 | 镜头太长 + 素材静态 | >12s 要配持续事件，或缩短 |
| 车内/运动镜头"像在颠簸" | 提示词写了 `camera swaying with the suspension` / `handheld` | 相机写 **rigidly locked to the cabin**，只留极轻微高频振动 |
| 拐弯时窗外景物只平移、不变角度 | 只写"车在转弯"，没写转弯对窗外画面的后果 | 见下方「运动镜头的三条物理约束」 |
| 转弯镜头"像车要飞出悬崖" | 路面/护栏画得太远，露出下坠坡面 | 路面与护栏贴近画面下部，地面与路面齐平，负面词加 `steep drop-off` |
| 运动黏滞、景物慢吞吞平移 | **Lightning 4 步蒸馏 LoRA 的慢动作效应** | 换 8 步三相位采样（多一段带 CFG 的相位） |
| 负向提示词与首帧打架 | 负面词带题材假设（如解剖片不能用 `cgi/3d render/bioluminescence`） | **换题材必须重审负面词**，按镜头类型分套路由 |
| 生成成功却被判超时、重复提交 | 轮询上限 < 真实执行时间（显存吃紧时可达 60 分） | 上限 ≥2× 预期；**超时先查磁盘，不重试** |
| 磁盘兜底取到别的片的同名素材 | 输出目录多片共享，`s7_*.mp4` 重名 | 兜底必须按「前缀 + 提交时间」双过滤 |
| 概念帧"看着粗糙/廉价" | 媒介选错：实景/解剖题材用 SVG 硬画 | 抽象机制用 SVG，实景/解剖/光影用图像生成 |
| SVG 引线渲染成黑三角 | 开放路径默认 `fill:black`，被当闭合路径填充 | 引线/折线显式 `fill="none"` |
| 模糊元素周围出现硬边方框 | 滤镜区域只有 bbox 的 120%，模糊半径远大于对象时被裁 | 小元素别套大 `stdDeviation`，或扩大滤镜区域 |
| 无人值守队列首镜超时→整批中止 | 安全阀把"排队超时"当成模型/节点错误 | 只有"提交即失败"才是系统性错误，超时继续下一镜 |
| 同一镜提交两次，GPU 白跑 | 门控期间任务已跑完并从队列消失 | 提交前查队列 + 共享输出目录，有就接管/取回 |

## 素材生成：运动镜头的三条物理约束

凡涉及车、船、飞行、手持跟拍等**载具/运动镜头**，提示词必须显式交代三件事。
只写"车在转弯"是不够的——模型不知道转弯对画面意味着什么，就会退化成横向平移。

| 约束 | 要写清什么 | 反例（会出错） |
|---|---|---|
| **视角** | 相机相对载具的朝向（如：垂直于行进方向的真侧视），并排除错误视角 | 只写 "side window" → 模型漂成前方路面视角 |
| **车姿** | 车身姿态变化**对窗外画面的后果**（横滚→地平线倾斜几度；偏航→景物通过角度持续变化） | 只写 "car leans into a curve"，不写后果 |
| **轨迹** | 载具方向沿道路切线；入弯时近景摆向车身；景物通过角度**不是固定一个角度** | 全程 `streak past horizontally` = 假设永远直行 |

外加两条：
- **相机刚性固定**：`camera rigidly locked to the cabin, no handheld shake, no bumps, only a faint high-frequency engine vibration`。写 `swaying with the suspension` 就是主动要求颠簸。
- **车内固定参照物**：窗框、头枕、座椅剪影相对镜头不动——这是让观众读懂"外面在动"的锚点。

## 素材生成：采样器与"慢动作效应"

Wan2.2 Lightning 4 步蒸馏有明显**运动迟缓**倾向：画面会动，但动得黏滞，该转向的地方只做平移。
这不是提示词能解决的，是采样器层面。

| 方案 | 结构 | 用途 |
|---|---|---|
| 4 步（默认） | HIGH(0→50%) → LOW(50→100%)，全程 cfg=1 | 快，适合静态/微观/缓慢镜头 |
| **8 步（三相位）** | HIGH+**cfg3.5**(0→25%) → HIGH+cfg1(25→50%) → LOW+cfg1(50→100%) | 有载具运动、需要真实转向的镜头 |

8 步开头那段带 CFG 的相位就是用来打破蒸馏惰性的。代价：耗时约翻倍。
判据：**先看 4 步版，运动"黏"就上 8 步**，不要先怀疑提示词。

## 素材生成：无人值守队列的三条铁律

单镜几十分钟，实际都要挂机跑。这类队列最容易出的不是崩溃，是**静默错**。

**时间预算**：同模型同分辨率下单镜耗时落在稳定区间（704×1280×121 帧约 25–36 分钟），**被抢卡翻倍**。按它估总时长、定超时上限（≥2× 上限）。

| 铁律 | 做法 |
|---|---|
| **排队 ≠ 执行** | 超时只算正在执行的时间；每轮轮询先查是否仍在队列，在就续期 |
| **判失败前先查磁盘** | 只有「不在队列 + 没成功 + 没落盘」才是真失败。直接重试 = 同一条 GPU 活干两遍 |
| **提交前先查队列和共享输出目录** | 门控等待期间任务可能已跑完并从队列消失；查到就接管轮询或直接取回 |

另外：安全阀只抓"提交即失败"这类系统性错误（超时/队列消失不算）；断点续跑（产物够大即跳过）；**绝不抢占**——不调 `interrupt`、不清别人队列。

### 卡死 ≠ 慢：先分清再处置

队列长时间不动，别默认"GPU 慢/在排队"。**慢只需等，卡死要重启服务**，处置相反。三条判据：

| 判据 | 含义 |
|---|---|
| 长时间占 running 首位却无产出 | 正常单镜是稳定区间，超过 2~3 倍仍无产物即异常 |
| `/history/<pid>` 返回**空** | 既无 success 也无 error——不是失败，是执行线程已挂 |
| `POST /interrupt` 返回 200 但队列无变化 | 线程不响应中断，等下去不会自愈 |

**卡死比"自己慢"严重**：占着显存不放，后面排队的任务（含别人的）一起被堵死。三条同时成立就立即处置：停自己的队列 → 按**原启动参数**重启服务 → 确认显存回落 → 重新排队未完成镜头。重启会清空队列、丢掉别人的任务，**属破坏性操作，须先征得同意**。
