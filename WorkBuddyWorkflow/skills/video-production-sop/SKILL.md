# 代码逐帧渲染视频 · 通用生产流程（video-production-sop）

## 何时使用

- 制作或修改**画面由代码按时间计算**的短视频：知识科普、数据解说、产品演示、动画短片。
- 竖版（9:16）与横版（16:9）都适用；本文的具体数值来自竖版参考实现，换画幅只需改参数。
- 排查这类管线的问题：文字消失、慢放掉帧、音画错位、生成 OOM、成片"卡住"。
- 不适用：真人口播、纯剪辑（非代码渲染）、复杂三维。

> 完整方法论（七参数决策表、迁移清单、判据来源）见仓库 `WorkBuddyWorkflow/视频制作通用流程.md`；
> 本文是给执行用的浓缩版，判据与硬规则优先。

## 核心思想

1. **逐帧确定性渲染**：所有动画是时间 `lt` 的纯函数（`render(lt)` / `FNS.sN(lt,t,el)`），任意一帧可复现、可定位、可对比。
2. **三层分离**：素材层（AI/实拍/渲染）+ 覆盖层（文字图形，透明）+ 音轨，各自生成后一次性合成。
3. **量化质检**：不靠"看着还行"，靠判据（最长静止 ≤3s、时长误差 ≤0.06s、关键帧像素特征）。

**后三条管工期，不改画面质量，但能砍掉大半墙钟时间**（来自第二支片复盘：59 小时里只有 16% 在真正生成）：

4. **关键路径**：GPU 是最贵最不可控的资源。代码能渲染的绝不排 GPU；GPU 任务**最早提交**，然后并行写覆盖层，别串行等。
5. **假设先跑小样**：任何"换参数会更好"的判断，写进文档前必须有单镜验证。没验证的建议比没建议更危险。
6. **验收双轨**：自动判据抓不到断字、结构画错、构图难看。成片必须**人眼抽帧 2 轮 × 8~9 帧**覆盖全片。

## 时间模型（一切对齐的基准）

| 项 | 规则 |
|---|---|
| 节奏基准 | 有 BGM 用 BPM（每拍 = 60/BPM）；无 BGM 用固定镜头时长 |
| 分镜时长 | `拍数 × 每拍` —— 唯一公式，素材层与覆盖层都必须服从 |
| 全片 | **总拍数守恒**：Σ拍数 × 每拍 = 成片时长 = 音轨时长 |
| 帧率 | 全片统一（参考实现 24fps）；素材层与覆盖层必须一致 |
| BGM | 合成时**不加 `-shortest`**（会裁尾帧） |

参考实现实例：BPM 112.3 → 每拍 0.53406s；256 拍 = 136.719s；14 镜。**数值是示例，不是规范。**


**三条铁律**
1. 改 `timeline.json` 后必须重生成 `timeline.js`（浏览器只读 js）。
2. **拍数变了的镜头必须重建 base 分段**，否则旧分段与新时间轴错位。
3. 覆盖层按全局 `t` 驱动，base 按拼接顺序对齐——两边都只认 timeline，不要各自写死时间。

## 八步流程

> 命令与路径是**参考实现**（仓库 `WorkBuddyWorkflow/src|scripts`）的写法。换项目/换画幅时替换成你的路径，
> 步骤顺序与判据不变。

1. **定节奏**：改 `src/timeline.json` → `python scripts/build_timeline.py`，核对总拍数与每镜时长。
2. **概念首帧**：`src/cN.html` → `node scripts/concept_render.js <N>` → `out/ai/concepts/cN.png`（704×1280）。
   - **媒介按题材选**：抽象机制/图表/数据用 SVG·HTML（精确可控）；实景/解剖/光影/氛围用**图像生成**（材质与景深 SVG 做不出来）。选错媒介，"粗糙"是必然的，不是细节问题。
   - 抽象感受要落在一个实物上（"闭眼后的黑暗"→全黑空画面；"闭眼特写+眼睑透光"才成立）；解剖类必须给**视角+部位名**。
   - 批量出完先拼一张总览图看风格一致性，比逐张 review 快一个数量级。
3. **生成底板**：提示词写进 `scripts/wan22.py` 的 `SCENES[N]`（四查：细节充分/契合功能/同向概念帧/区别于他镜），`python scripts/gen_one.py <N> <seed> 121`。
   - **必带运动**：不写 "completely still"；写慢眨眼、呼吸、光效明灭、极缓推近。静止素材会触发节奏缺陷。
4. **建底板**：`python scripts/build_base.py 3,7,13`（只重建改动镜头）。配置项：`LOOK` 调色/特效、`TRIM/TRIM_END` 裁头尾、`PARTS_TIMED` 分段定速、`GEO` 改构图、慢放 `setpts+minterpolate`。
   - **分段帧数按累计边界取整**：`cum += target; n_end = round(cum*fps); n_frames = n_end - prev_n`。逐段各自 `round` 会让取整误差同向累加——单段 0.01s 的偏差，十几段就能漂出 0.3s，超出全片 0.06s 容差。判据要两条：每段 ≤0.06s **且** Σ段帧数 = `round(总时长×fps)`。
5. **做覆盖层**：在 `src/index.html` 的 `<section id=sN>` 加 `data-t/data-anim/data-d`；需要逐帧逻辑写 `FNS.sN(lt,t,el)`；卡点光效配 `FLASH[N]`。
6. **单镜预览（每次改画面必做）**：`node scripts/scene_preview.js s6 5 --base`，秒级出图，查排版/时序/构图 + JS 报错。
7. **合成**：`node scripts/composite.js 24`（Puppeteer 逐帧截图 → ffmpeg 叠加 base+BGM）。吞吐约 **8fps**（1080×1920），2 分钟片约 7 分钟——合成不是瓶颈，别为省它砍质检。
   - **工具链用自带的二进制**：ffmpeg 不必装系统版（`imageio-ffmpeg` 自带，`get_ffmpeg_exe()` 取路径，抽帧/混流/`volumedetect` 都够）；无头浏览器直接指 Playwright 的 Chromium（`CHROME_EXECUTABLE_PATH` + `CHROME_HEADLESS=true`）。
   - **Remotion 入口是 `./node_modules/.bin/remotion`**：用 `node node_modules/@remotion/cli/dist/index.js render …` 会**退出码 0 却零产出**；输出路径必须相对 cwd。渲染完**必须 stat 产物**，别只看返回值。
   - **BGM 用既定母版**：**优先做成与母版等长**（母版自带淡出就是成片收尾，最干净）；讲不满才截取前 N 秒 + 尾部 `afade=t=out` + `volume=-1dB` 余量。**不要为每片现合成**——BGM 是账号的听感资产，重合成等于每片从零建立辨识度。混流用 `-t <成片时长>` 精确截断，**不加 `-shortest`**。定顺序：先看母版多长、再定内容量，别先定时长再找音乐（必然硬切或淡出点落在乐句中间）。
8. **质检交付**：`python scripts/qc_rhythm.py` 必过 + `ffprobe` 音画时长一致 + 关键帧像素抽检 + 音频电平（mean≈-15dB，**峰值留 ≥1dB 余量**，触顶即削波）。质检脚本**分辨率自动探测**（`ffmpeg -i` 正则），横竖版共用一套判据——写死尺寸换画幅后会静默算错分区。

## 七条硬规则（违反必出 bug）

**渲染五条**
1. **禁止 CSS transition / keyframes**——逐帧 seek 会抖，动画全部由 `render(lt)` 计算。
2. **禁止 `Math.random()`**——每帧重算会跳，用确定性 `rng(seed)`。
3. **禁止 `background-clip:text`**——无头 Chrome 合成层丢渐变填充（字变透明）；用纯色 + text-shadow 光晕。
4. **带样式的原子标签不可拆字**（`tx-grad/tx-mark/tx-serif` 等），拆了样式丢失、字消失。
5. **慢放素材要与动画同步**：视频放慢 K 倍时，在 FNS 首行 `lt/=K` 把本地时间压回设计时刻表（保证动作落点仍等于画面事件）。

**工程两条**
6. **单镜样式必须 `#sN` 限定**——改 `.txt/.h1` 这类全局类会移动全片所有镜头。判断：这次是"这一镜特殊"还是"全片都该变"。
7. **绝对定位块必须算垂直占位**——同 section 多个 absolute 块的 top/bottom 各写各的，重叠在缩略图上看不出来。排完版列一遍 `top` 与 `top+高度` 确认无交叠；文字块高度随内容变，别只看首行。

## 三道质检闸门

| 闸门 | 工具 | 判据 | 时机 |
|---|---|---|---|
| ① 单镜 | `scene_preview.js` | 无 JS 报错；排版不压主体；**文字与底板亮部对比度**；时序 | 每次改画面 |
| ② 节奏 | `qc_rhythm.py` | **每镜最长静止 ≤3.0s**；静止占比>45% 提示。静止按**变化像素占比**算 | 合成后 |
| ③ 成片 | ffprobe + 像素统计 | 时长严丝合缝；关键帧特征（如落点、文字带亮度、光效搏动）；音频 mean≈-15dB 且峰值不触顶 | 交付前 |

### 闸门①之前：先确认预览工具可信

**这是最容易骗人的一环。** 预览若没真正叠上底板，看到的"干净画面"是假的——排版完美，成片里文字全压在亮背景上。

- **自检法**：挑一个你确定应该出现的底板特征（柱子/人脸/星空），预览里必须看得见。看不见 = 叠加链路断了，先修工具。
- 预览脚本里任何"为了好看"设的底色/背景都会破坏透明叠加，一律不要加。
- 曾踩：`scene_preview.js` 给 body 设不透明底色，连续几轮预览都说"没问题"，合成才暴露 s8 文字压柱。

### 覆盖层框架：新片新建，别抄旧片

旧片的 `render` 与它自己的场景结构强耦合（硬编码 `.s3head`、`.s7head` 这类按镜号起的类名），照抄会把旧片构图假设一起带进来。**可复用的是驱动模型，不是代码**：

- **元素级声明式驱动**：`data-t`（本镜相对秒）+ `data-anim`（rise/fall/scale/pop/left/right/blur/fade）+ `data-d`（时长），逐帧由统一 `render(t)` 计算
- 只有声明式表达不了的特殊效果才写 `FNS.sN(lt,t,el)`
- 效果：九成镜头只改 HTML 属性不碰 JS；节奏调整集中在一处，不会漏镜头

### 透明模式：URL 参数只是开关，样式还得自己加

`?ov=1` 是**信号不是行为**，样式仍要在脚本里给 `html`/`body` 加透明类（如 `.ov{background:transparent}`）。漏了这步底色仍是 `#000`，截图带黑底，叠底板时把素材**整帧盖掉**——表现是"预览只有文字、背景全黑"。

**预览干等超时先查依赖**：预览靠 `window.TIMELINE` 就绪后置位 `__ready` 再截图。忘引时间轴脚本 → `TIMELINE` 空 → `__ready` 永不置位 → 白等超时。超时先看脚本加载与就绪标志，别先怀疑动画代码。

### 文字可读性：自动判据测不到的第四道关

文字与素材层分开开发，"文字压亮部"只有合成后才暴露，而帧间能量/时长/电平都不管对比度。
→ 设计文字位置时就看底板亮度；素材有亮区（人脸/发光物/窗帘）时，文字**加底衬或错位**，二选一。

### 排版：先算单行容量，别掉出孤字行

同类"自动判据测不到、只有抽帧才看得见"的缺陷还有**折行**。

- 中文全角 ≈ 1em，**单行字数 ≈ 容器宽 ÷ 字号**（留 5% 余量）：72px 配 900px 容器约 12 字。
- 超了不报错，只把末尾两三个字挤成一行——对比度/能量/时长判据都不管换行，**只能抽帧看**。
- 修法：**降一级字号**（h2→h3，保留层级）> 拆句 > 收窄内边距。长句降一级往往更合层级。
- 排完版做**字数核算**：逐行算「字数 ÷ 字号」vs「容器宽 ÷ 字号」，超的直接重排。
- **字数会变的元素要自适应字号**：印章、字牌、标签这类固定容器里放 2~6 个字，字号写死就会"两字撑满、六字溢出"。按「容器宽 ÷ 字数 × 系数」算，或按字数分档。

### 画面风格与构图基线

**换画幅不是缩放，是重排版式。** 开工前先定三条水平线，所有元素往上挂：

| 画幅 | 地平线 | 字幕带 | 分区 |
|---|---|---|---|
| **横版 16:9**（默认，1920×1080） | y ≈ 760~800 | y ≈ 880~1040 | 左巨字字牌 + 右条目卡；纪年条改**右上横排胶囊** |
| 竖版 9:16（1080×1920） | 中部偏下 | 下三分之一 | 竖排纪年条贴侧边；信息自上而下堆叠 |

- 别把竖版的"上下堆叠"搬到横版——会得到左右两片空白；宽画幅要么信息分列，要么场景横向铺满。
- **视觉基线是"插画感剪影 + 丰富动效"，不是扁平简笔**：扁平简笔省掉材质与光、只剩形状，所有画面都像 PPT 图表。

| 层次 | 做法 |
|---|---|
| 场景 | 剪影化多层景（山脊/城墙/人群），靠**层次**立住，不靠细节 |
| 运动 | 多层**视差**（远慢近快）+ 角色步行/奔跑**循环** + 环境光**渐变**（黄昏→夜→黎明用 RGB 插值，别切色块） |
| 戏剧动效 | 关键节点给大动作：数字砸屏 + 镜头抖动、牌位连环倒、披袍（`scaleY` 肩到脚）、光芒放射、盖章 |
| 质感 | 墨色 × 鎏金这类双色体系；纪年条做"史料感"锚点 |

判据：随便截一帧，看得出"这是个场景"而不是"几个色块"。做不到是缺层次与光，不是缺细节。

### 文案结构：钩子公式 + 问题链

前两秒只有一句话的容量，用**结构化句式**而不是自由发挥：

| 环节 | 句式 | 作用 |
|---|---|---|
| 钩子 | 「明明只是……，怎么就……」 | 摆出日常经验，制造"我也遇到过" |
| 反转 | 「这不是……，是……」 | 一句话给因果，3 秒内兑现悬念 |
| 收尾 | 「愿你……」 | 从知识回到人，避免"讲完就断" |
| 系列化 | 「第 N 集｜系列名｜主题」+ 下集预告 | 同一批观众被下一集接住 |

**长内容用"问题链"组织，不写流水账**：先列观众会问的 3~4 个问题，一幕答一个，幕间是"回答上一问引出的下一问"。内容多就**加镜头**，别压时长——压时长会压断因果链，观众只记住结论不记住推理。

### 判据在测什么（决定你能怎么改）

**第一步是选对度量，不是调阈值。** 同样是"帧间差异"，两种算法结论会相反：

| 度量 | 算法 | 失效方式 |
|---|---|---|
| 全帧平均灰度差 | 下采样灰度，逐帧求全画面平均差 | 深色底 + 局部小动画（滚动条/计数/盖章）时均值差 <1.5/255，**活镜头被判 3s 以上静止**（假阳性） |
| **变化像素占比**（默认） | 单像素变化 >6 灰度记为"变"，统计占比，阈值 ~0.3% | 对全屏缓慢渐变不敏感（那本不算"事件"） |

换度量后**重跑一支老片校准**，别搬旧阈值。指标恢复真实含义时，自动检出的切点会与镜头边界对上——这是免费的结构校验。

**第二步是记住它只测"有没有变化"**：
- 小元素推不动它：r=8 光点占屏面积远低于阈值（实测加四段尾迹只降 2 个百分点）。
- 要推动它必须**硬边缘 + 高对比**：判据先把画面下采样（分析尺度常 270px 宽量级），**柔光呼吸/渐变明暗会被采样抹平**——像素差 <6 灰度，数值上零运动，人眼却觉得"在呼吸"，这是**伪运动**，救不了判据。
- 有效的三类：**硬边缘粒子**（小也行，边界锐利 + 逐帧位移 ≥2px）、**高对比长线条**扫过（指针/旗面）、**大面积高幅度**位移（不是低幅度呼吸）。
- **通过 ≠ 观感好**（花哨廉价的运动也能过）；**不通过 ≠ 难看**（收尾定格本该静）。

**第三步：任何单一数值指标都要与人眼抽帧交叉验证。** 指标说"通过"抽帧看是否真在动；说"静止"抽帧看是否真有变化。

**正确用法**：用它发现漏掉的死角，不是刷分。发现后先问"为什么这么久没变化"——答案通常是**镜头太长**或**素材本身静态**，要改结构而非加特效。

### 改完之后：用差分证明"只改了该改的地方"

改一处文字后，两版成片肉眼对比不可行，"看着没坏"也不等于没波及。

1. 取改前/改后**同一帧号**的帧 → 灰度相减 → 统计**差异像素总量**
2. **逐行扫描**差异带，应正好落在被改元素所在行
3. 设**对照区**（画面中部/未改动的镜），应为 **0% 变化**

判据：差异量与改动文字面积**同量级**，无关区零变化。远大于 → 有连带位移；为零 → 改动没生效（没重渲，或改的是没被引用的那份文件）。

⚠️ 按 CSS 的 `bottom` 反推 y 坐标经常算错——先扫全图找差异带，再读坐标。这条路也是**读不了图时的兜底**：像素统计照样能回答"生效了吗、波及别处了吗"。

## 交付：发布物料（封面 / 文案 / 合规）

成片过闸门只是"能播"，投放前还有一层物料，最容易错在**取错源**和**漏标注**。

| 项 | 做法 | 为什么 |
|---|---|---|
| 封面 | 写成 HTML 版式，宽高与底图走 URL 参数（`?w=&h=&bg=`），一套模板渲多尺寸；宽 > 高自动切横版布局；出图用渲染器**单帧命令**（如 `remotion still`），与成片共用组件 | 各平台各做一版必然逐渐不一致；另起一套封面工具链会与成片风格分叉 |
| **封面底图** | 从**素材层**（`base` 分段）抽帧 | 成片已烧入覆盖层文字/标签，抽帧带文字残影，会和封面新加的字叠在一起 |
| **章节时间码** | 按「拍数 × 每拍时长」从时间轴换算 | 手记秒数必与画面错位，节奏一改更难对 |
| **AI 标注** | 画面含 AI 生成内容时标注"内容由 AI 生成" | 只勾"原创"不标注有限流/下架风险 |

✔ 判据：封面与成片同一版式体系、无文字重影；章节点逐条跳转对得上画面；平台必填项（AI 声明/合集/话题）齐备。

**上传：半自动填表，发布键留给人**（平台无个人开放 API）

| 环节 | 谁做 |
|---|---|
| 登录（扫码） | 人 |
| 上传视频 / 标题 / 简介 / 话题 | **脚本** |
| 封面（弹窗裁剪框抓不到句柄）、自主声明、合集 | 人 |
| **点发布** | **人** |

四个坑：① 扫码后跳首页，找不到控件要重新 `goto` ② 用 `networkidle2`，`domcontentloaded` 太早
③ **话题上限 5 个** ④ **脚本退出会关浏览器、表单全丢** → 结尾 `setInterval` 常驻

参考：`scripts/douyin_upload.js`

## 交付：数据回流（看 2 秒跳出率）

**播放量由推荐量决定，不是内容质量的信号。** 该看留存曲线最左端：

| 指标 | 用途 |
|---|---|
| **2 秒跳出率** | 最早最灵敏，只反映"封面承诺 + 第一帧"是否成立 |
| 5 秒完播率 | 反映钩子，但滞后 |
| 完播率 | 60s 以上意义有限 |

实测基线 **45~50%**（一半人两秒内走）。判据：改版后 **<30%** 说明钩子改造有效；
仍在 45% 左右 → 问题在选题或封面承诺，不在画面。

**发布后等 2 小时再读**，冷启动前 30 分钟波动极大。

## 一题两剪

完整版与平台版要求冲突，别用一条片子兼顾：

| | 完整版 | 高密度版 |
|---|---|---|
| 时长 | 90~140s | **30~45s** |
| 单镜 | 7~8s | **2~3s** |
| 开头 | 铺垫 | **结论前置，第 0 帧给反直觉** |

复用素材与覆盖层，只重排时间轴 + 重写文案，**约 30 分钟、零 GPU**。
手法：从素材**切 2~3 秒片段**，不是把 7.5s 压缩（那会变成快进）。
参考：`scripts/build_short.py`

## 踩坑速查（症状 → 根因 → 规则）

| 症状 | 根因 | 规则 |
|---|---|---|
| 字消失/透明 | `background-clip:text` 丢填充 | 纯色 + 光晕 |
| 慢放掉帧/幻灯片 | `fps` 复制帧 | `setpts` + `minterpolate=mi_mode=mci` |
| 拼接后总长被压缩 | 多段 xfade 塞一条 filtergraph，offset 错位 | 分步 concat，每步校验 |
| `-ss/-to` 时长不对 | 放在 `-i` 之后被当输出限制 | 输入侧裁剪，放 `-i` 前 |
| 生成 OOM（node 10） | 外部进程瞬时占显存，门控只看利用率% | 空闲显存硬门槛（≥9GB） |
| 误判"两个 ComfyUI 抢端口" | venv 与 uv python 是父子进程=同一服务 | 查 ParentProcessId |
| 后台任务莫名消失 | shell 里加 `&` 随 shell 退出被连坐 | 用托管后台任务 |
| 成片下部很黑 | `.ov-scrim` 覆盖层压暗渐变，设计如此 | 勿与未加 scrim 的底板对比误判 |
| 慢推加了没效果 | 镜头级速率（5%/1.5s）拉长到整镜慢 20 倍 | 镜头级用，或换素材 |
| 周期性光效"无差异" | 跨拍抽帧被底板慢漂移混淆 | 抽**同拍相邻帧** |
| 单镜时长错位 | 改了 beats 却复用旧分段 | 改拍数必须重建该镜 |
| 预览"排版完美"，成片文字压背景 | 预览脚本给 body 设不透明底色，底板被盖掉 | 预览保持透明 + 已知特征自检 |
| 透明模式预览只有文字、背景全黑 | 只加 `?ov=1` 参数，没在脚本里给 html/body 加透明类，底色仍 `#000` | 参数只是开关，样式必须同时改 |
| 单镜预览干等超时、无报错 | 没引时间轴脚本 → `window.TIMELINE` 空 → `__ready` 永不置位 | 超时先查脚本加载与就绪标志 |
| 队列十几小时无产出，任务仍占 running | 执行线程已挂（`/history` 空、`interrupt` 无效），不是排队慢 | 三判据确认后重启服务；会堵死整条共享队列 |
| 重启后队列又静止，毫无报错 | 服务由会话内后台任务启动，会话结束被回收 | 长跑服务脱离会话启动；启动命令记进文档，接手先探活 |
| 覆盖层照抄旧片，改一镜要动一堆硬编码类名 | 旧片 render 与旧场景结构强耦合 | 只复用驱动模型（`data-*` 声明式），代码新建 |
| 文字压亮部看不清，自动判据全过 | 对比度不在任何判据里 | 排版前看底板亮度；亮区加底衬/错位 |
| 加一堆小动效，静止占比只降 2% | 判据算全画面平均差，小元素贡献 <0.0005 | 用大面积/高对比；或改镜头长度 |
| 改一处样式全片移位 | 动了全局类 | 单镜改动带 `#sN` |
| 两块叠一起，缩略图看不出 | absolute 块各写 top/bottom，没算占位 | 排完版做占位核算 |
| 17s 镜头怎么加动效都闷 | 镜头太长 + 素材静态 | >12s 要配持续事件，或缩短 |
| 车内/运动镜头"像在颠簸" | 提示词写了 `camera swaying with the suspension` / `handheld` | 相机写 **rigidly locked to the cabin**，只留极轻微高频振动 |
| 拐弯时窗外景物只平移、不变角度 | 只写"车在转弯"，没写转弯对窗外画面的后果 | 见下方「运动镜头的三条物理约束」 |
| 转弯镜头"像车要飞出悬崖" | 路面/护栏画得太远，露出下坠坡面 | 路面与护栏贴近画面下部，地面与路面齐平，负面词加 `steep drop-off` |
| 扫码登录后自动化脚本卡住 | 登录成功会跳创作者首页，不在上传页 | 找不到控件就重新 `goto(上传页)` |
| 填好的表单突然全丢 | 脚本进程退出，puppeteer 把浏览器一起关了 | 结尾 `setInterval(()=>{},1<<30)` 常驻 |
| 话题标签被拦 | 平台上限 5 个 | 文案阶段就控制在 5 个 |
| 数据看着很差但刚发布 | 冷启动推流前 30 分钟波动极大 | 等 2 小时再读，主看 2 秒跳出率 |
| 运动黏滞、景物慢吞吞平移 | Lightning 4 步蒸馏的慢动作效应 | **先改提示词**（运动三约束）；8 步三相位在 FP8 权重上出伪影，默认不开 |
| 负向提示词与首帧打架 | 负面词带题材假设（如解剖片不能用 `cgi/3d render/bioluminescence`） | **换题材必须重审负面词**，按镜头类型分套路由 |
| 生成成功却被判超时、重复提交 | 轮询上限 < 真实执行时间（显存吃紧时可达 60 分） | 上限 ≥2× 预期；**超时先查磁盘，不重试** |
| 磁盘兜底取到别的片的同名素材 | 输出目录多片共享，`s7_*.mp4` 重名 | 兜底必须按「前缀 + 提交时间」双过滤 |
| 概念帧"看着粗糙/廉价" | 媒介选错：实景/解剖题材用 SVG 硬画 | 抽象机制用 SVG，实景/解剖/光影用图像生成 |
| SVG 引线渲染成黑三角 | 开放路径默认 `fill:black`，被当闭合路径填充 | 引线/折线显式 `fill="none"` |
| 模糊元素周围出现硬边方框 | 滤镜区域只有 bbox 的 120%，模糊半径远大于对象时被裁 | 小元素别套大 `stdDeviation`，或扩大滤镜区域 |
| 无人值守队列首镜超时→整批中止 | 安全阀把"排队超时"当成模型/节点错误 | 只有"提交即失败"才是系统性错误，超时继续下一镜 |
| 同一镜提交两次，GPU 白跑 | 门控期间任务已跑完并从队列消失 | 提交前查队列 + 共享输出目录，有就接管/取回 |
| 每段时长都合格，拼接后总长差 0.3s | 各段独立 `round(时长×fps)`，取整误差同向累加 | 按**累计边界**取整，Σ段帧数 = `round(总时长×fps)` |
| 长句末尾两三个字单独占一行 | 字数×字号 > 容器宽；超了不报错只折行 | 单行字数 ≈ 容器宽÷字号；降一级字号或拆句，只能抽帧发现 |
| 重启服务进程秒退，日志却干净 | 节点启动批量清理历史备份，被宿主批量删除保护杀掉 | 查宿主安全策略；目录**改名旁置**而非删除 |
| 偶发执行错误被当成配置问题 | 把单次 `execution_error` 当系统性错误 | 先原样重试一次，再怀疑配置 |
| 封面上的字与底图上的字叠在一起 | 封面底图从**成片**抽帧，成片已烧入覆盖层文字/标签 | 底图只从素材层（`base` 分段）抽 |
| 发布后被判非原创/限流 | 画面是 AI 生成，却只勾"原创"没标 AI | 按平台要求标注"内容由 AI 生成" |
| 深色底的活镜头被判"静止 3s 以上" | 静止检测用全帧平均灰度差，大片静止区稀释了局部动画 | 改用**变化像素占比**（单像素 >6 灰度，阈值 ~0.3%），与抽帧交叉验证 |
| 渲染脚本退出 0，却零产出 | 用 `node @remotion/cli/dist/index.js` 调 CLI，入口不对会静默成功 | 入口用 `./node_modules/.bin/remotion`；出片后 stat 产物 |
| 质检"全部通过"，其实一项没算 | 短版 timeline `beats=0`，时长按 `beats×beatSec` 算成 0，分母为空 | 时长优先取显式 `dur`；判据脚本要校验输入完整性 |
| 每支片 BGM 听感都不一样 | 为每片临时合成新曲，低频重心与节奏密度在漂 | 用既定**母版**按片长截取 + 尾部淡出，不现合成 |
| 音频切片报 `slice indices must be integers` | 用累加浮点当数组索引（`start += 0.5`） | 累加后立刻 `int()`，或用帧号算边界 |
| 改一处文字，无法确认是否波及别处 | 两版成片肉眼对比不可行 | 同帧号灰度差分 + 逐行扫描，差异量 ≈ 改动面积、无关区 0% |
| 编译报 `symbol already declared` | 文件内复用的小图形与导出组件**同名**（`const Mirror` vs `export const Mirror`） | 局部图形改名加后缀（`MirrorPanel`），导出名留给场景组件 |
| 复用旧组件时编译报"属性不存在" | 按记忆传了该组件未定义的 prop（如 `opacity`） | 复用前先看 props 签名，别凭印象传参 |
| 渲染到某一帧突然 `ReferenceError`，前面全正常 | 增删/重写场景时漏了组件引用，只有该镜首次出现那帧才求值 | 先渲**前 12 帧小样**（`--frames=0-12`），或按崩溃帧号 grep 日志 |
| 加了柔光呼吸/渐变，静止判据一点没降 | 下采样后软过渡被抹平，像素差 <6 灰度 → **伪运动** | 环境动效用硬边缘高对比元素（粒子/长线条） |
| 印章放两个字撑爆、四个字空一半 | 容器固定、字号写死，字数一变比例就崩 | 字号按字数自适应或分档 |
| 换横版后分区判据全偏，报告却显示通过 | 质检脚本把分辨率写死成竖版，裁剪坐标按旧画幅算 | 分辨率从 `ffmpeg -i` 正则解析，横竖共用一套判据 |

## 素材生成：默认代码渲染，AI 只作例外

**GPU 慢、要排队、会被占满、会卡死。所以判断顺序是「先问能不能代码做 → 不能 → 才用 AI」，不是反过来。**

| 镜头类型 | 用什么 | 理由 |
|---|---|---|
| **结构 / 解剖 / 机械 / 图表 / 流程** | **代码渲染** ← 默认 | 几何关系本身就是信息；参数可控、13 秒出片 |
| **抽象概念**：信号流、冲突、能量、光效 | **代码渲染** ← 默认 | 语义明确，AI 容易画成无意义炫光 |
| **拟人 / 角色动画**：动物、人物动作、载具运动 | **代码渲染** ← 默认 | 骨骼 IK、轮系传动、循环动作，代码写出来是确定的 |
| **实景**：真实人脸、车内实拍感、自然风光 | **AI 生成（I2V）** | 只有这类代码确实做不出来 |

**一句话判据**：
- 「这一镜**必须看起来像真的**吗？」→ 不必须 → **代码**
- 「必须是真实质感的实景吗？」→ 是 → **AI**

**"鹈鹕测试"是最好证明**：一句 `Generate an SVG of a pelican riding a bicycle, with animation`，
模型直接写 SVG + 动画，浏览器渲染，**零视频生成模型**。
车轮自转、踏板圆周、腿的 IK 跟随、身体起伏、背景滚动与轮速匹配——全是数学。
参考 `remotion/src/PelicanBike.tsx`，1080×1080/24fps/5 秒，**渲染 15 秒**。

**代价（实测）**：AI 单镜 25~30 分钟（GPU），改一版再等半小时；
代码渲染 **13~15 秒**（CPU），改参数十几秒出结果。首次编写 10~20 分钟，可跨片复用。

**结构类镜头 AI 的失败方式不是糊，是"似是而非"**：
说"三个半规管"，它给三根交叉细线框，观众数不出三个。**精致 ≠ 准确。**

参考实现：`WorkBuddyWorkflow/remotion/`（Remotion 4 + SVG，规格对齐 704×1280/16fps/121 帧）。

## 素材生成：运动镜头的三条物理约束

凡涉及车、船、飞行、手持跟拍等**载具/运动镜头**，提示词必须显式交代三件事。
只写"车在转弯"是不够的——模型不知道转弯对画面意味着什么，就会退化成横向平移。

| 约束 | 要写清什么 | 反例（会出错） |
|---|---|---|
| **视角** | 相机相对载具的朝向（如：垂直于行进方向的真侧视），并排除错误视角 | 只写 "side window" → 模型漂成前方路面视角 |
| **车姿** | 车身姿态变化**对窗外画面的后果**（横滚→地平线倾斜几度；偏航→景物通过角度持续变化） | 只写 "car leans into a curve"，不写后果 |
| **轨迹** | 载具方向沿道路切线；入弯时近景摆向车身；景物通过角度**不是固定一个角度** | 全程 `streak past horizontally` = 假设永远直行 |

外加两条：
- **相机刚性固定**：`camera rigidly locked to the cabin, no handheld shake, no bumps, only a faint high-frequency engine vibration`。写 `swaying with the suspension` 就是主动要求颠簸。
- **车内固定参照物**：窗框、头枕、座椅剪影相对镜头不动——这是让观众读懂"外面在动"的锚点。

## 素材生成：采样器与"慢动作效应"

Wan2.2 Lightning 4 步蒸馏有明显**运动迟缓**倾向：画面会动，但动得黏滞，该转向的地方只做平移。

| 方案 | 结构 | 实测结论 |
|---|---|---|
| **4 步（默认）** | HIGH(0→50%) → LOW(50→100%)，全程 cfg=1 | **可用**，所有镜头都用它 |
| 8 步（三相位） | HIGH+cfg3.5(0→25%) → HIGH+cfg1(25→50%) → LOW+cfg1(50→100%) | **本地 FP8 权重上不可用** |

⚠️ **8 步三相位实测是坏的**：在 `wan22EnhancedLightning_v2I2VFP8HIGH/LOW` 上出现
水平扫描线撕裂 + 青橙互补色边 + 硬边破形。根因是开头 `cfg=3.5` 对已蒸馏的 FP8 权重过猛，
把潜变量推出分布。**慢动作没解决，先出伪影。**

判据：运动"黏"时**先改提示词**（运动镜头三约束），不要先动采样器；
真要试 8 步必须**先跑单镜小样**，确认无伪影再批量。默认不开。

## 素材生成：无人值守队列的三条铁律

单镜几十分钟，实际都要挂机跑。这类队列最容易出的不是崩溃，是**静默错**。

**时间预算**：同模型同分辨率下单镜耗时落在稳定区间，但**随 GPU 争用浮动很大**——704×1280×121 帧独占 GPU 约 17 分钟，被抢卡 25–36 分钟甚至翻倍。基线记"独占 / 争用"两档，估总时长与定超时上限（≥2× 争用值）都按坏的一档。

| 铁律 | 做法 |
|---|---|
| **排队 ≠ 执行** | 超时只算正在执行的时间；每轮轮询先查是否仍在队列，在就续期 |
| **判失败前先查磁盘** | 只有「不在队列 + 没成功 + 没落盘」才是真失败。直接重试 = 同一条 GPU 活干两遍 |
| **提交前先查队列和共享输出目录** | 门控等待期间任务可能已跑完并从队列消失；查到就接管轮询或直接取回 |

另外：安全阀只抓"提交即失败"这类系统性错误（超时/队列消失不算）；断点续跑（产物够大即跳过）；**偶发 `execution_error` 先原样重试一次**（实测即过），别当配置问题去改模型/参数；**绝不抢占**——不调 `interrupt`、不清别人队列。

### 卡死 ≠ 慢：先分清再处置

队列长时间不动，别默认"GPU 慢/在排队"。**慢只需等，卡死要重启服务**，处置相反。三条判据：

| 判据 | 含义 |
|---|---|
| 长时间占 running 首位却无产出 | 正常单镜是稳定区间，超过 2~3 倍仍无产物即异常 |
| `/history/<pid>` 返回**空** | 既无 success 也无 error——不是失败，是执行线程已挂 |
| `POST /interrupt` 返回 200 但队列无变化 | 线程不响应中断，等下去不会自愈 |

**卡死比"自己慢"严重**：占着显存不放，后面排队的任务（含别人的）一起被堵死。三条同时成立就立即处置：停自己的队列 → 按**原启动参数**重启服务 → 确认显存回落 → 重新排队未完成镜头。重启会清空队列、丢掉别人的任务，**属破坏性操作，须先征得同意**。

**重启起的服务必须能脱离会话存活**：用会话内后台任务启动的常驻服务，会话一结束就被回收，队列再次静止且无任何报错。把完整启动命令（含显存参数）记进文档，交给独立进程托管；接手时先探活（能查队列/显存有占用），再查别的原因。

**重启时进程秒退、服务日志却干净 → 先怀疑被宿主安全策略杀掉，别改配置**：典型是自定义节点启动时要批量清理历史备份/缓存（几十上百个文件），被宿主的批量删除保护直接终止，标记只留在宿主侧。处置：把该目录**改名旁置**（不删，占几 MB），无旧文件可清即可启动；这类目录会重新堆积，**每次重启都可能复现**，属已知项。
