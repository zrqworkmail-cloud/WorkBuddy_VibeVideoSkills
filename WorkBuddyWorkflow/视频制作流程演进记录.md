## 一、当前流程是什么（一句话版）

```
概念帧(SVG→PNG) → ComfyUI/Wan2.2 I2V 生成底板素材 → ffmpeg 建 base 分段
   → Puppeteer 逐帧渲染透明覆盖层(data-t + FNS 动画) → 覆盖层 × base × BGM 合成成片
```

核心优势：**完全确定性**（`render(lt)` 按全局时间逐帧算，无 CSS transition/随机数），
所以任何一帧都能复现、能定位、能对比。这是它对的方向，不要动。

## 二、实测痛点（这次做片真实卡住的点）

| # | 痛点 | 具体表现 | 代价 |
|---|------|---------|------|
| 1 | **改一个字要全片重渲染** | 覆盖层 3281 帧逐帧截图 + ffmpeg，一轮 ~30–40 分钟 | 每调一句文案/一个字号就是半小时起 |
| 2 | **ComfyUI 生成脆弱** | 双专家第二段 `KSampler(node 10)` 峰值 ~9–10GB；被外部进程瞬时抢占显存就 OOM | 白等 9–15 分钟还失败；本次 s14 连挂两次 |
| 3 | **GPU 门控只看利用率** | `gpu_gate` 原来只查 util%，漏判"利用率 3% 但显存被占 9GB" | 带着 OOM 风险提交 |
| 4 | **机理动画各写各的** | HPA 轴(s5)、奖赏回路(s6)、生物钟曲线(s4/s13) 都是手写 SVG+JS | 新加一个机理分镜要 ~100 行 |
| 5 | **QC 靠整片** | 想看某分镜文字排版/时序对不对，只能等整片出来 | 反馈回路太长 |

## 三、已经落地的优化（本次已改进代码）

1. **`gpu_gate.py` 加"空闲显存下限"硬门槛**（`GPU_FREE_FLOOR_MIB = 9000`）
   - 提交前除利用率外，还要求空闲显存 ≥ 9GB；不足就让渡等待。
   - **这道门槛能直接挡住本次 s14 的 OOM**——它挂就是因为外部进程瞬时占了 ~9GB，而旧门控看利用率只有 3% 就放行了。

2. **`scene_preview.js` 单镜秒级预览**（新工具）
   - 只渲染目标分镜的覆盖层，`--base` 时叠到底板对应帧，采样几帧出图。
   - 调文案/字号/时序时 **~15 秒** 出结果，替代 30 分钟全片重渲染。这是反馈速度提升最大的一个。
   - 例：`node scripts/scene_preview.js s6 5 --base`

3. **s3 放慢与文案重排**：`FNS.s3` 用 `lt/=1.25` 把本地时间压回"设计时刻表"，
    Morph/读数/文案随更慢的眼视频一起延展，**水滴落点仍精确等于眼皮合上那一拍**——
    "视频慢一点"和"声画同步"不再二选一。

## 四、可评估的 skill / 插件 / 内置工具

| 能力 | 现状 | 建议 |
|------|------|------|
| **内置 `VideoGen`**（文/图→短视频 mp4） | 可用（deferred 工具） | 给**非关键空镜/B-roll/预演**做快速备选：无需 GPU 门控、无 9 分钟等待。缺点：时长偏短、对"逐帧确定性合成"管线控制力弱。建议对 1–2 个氛围镜做 A/B 对比再决定是否引入 |
| **内置 `ImageGen`**（文→图） | 可用（deferred 工具） | 用来生成**更精致的 I2V 概念首帧**（现在用 `concept_render.js` 画 SVG 首帧；ImageGen 可能给出更有质感的第一帧，喂给 Wan2.2） |
| **技能市场（视频类 skill）** | 本环境市场不可用（404） | 暂无专门"视频生成"技能可装；不虚构。真正的提速在工作流层（见三） |
| **连接器（视频/素材类）** | 无匹配项 | 本地 ComfyUI + ffmpeg + Puppeteer 已是合适栈，不建议为此接外部服务 |
| **办公类 skill**（pptx/docx/sheet） | 可用 | 与视频无关；仅当要把分镜表/台词导出成文档时用 |

> 结论：**没有"装个 skill 就提速"的银弹**。这套流程的提速点在工程层——①单镜预览（已做）②显存门槛（已做）③机理动画模板化（建议做）。

## 五、建议的后续采用顺序（按性价比）

1. **马上用**：`scene_preview.js` —— 之后每次改文案都先跑它，确认再全片合成。
2. **已生效**：`gpu_gate` 显存门槛 —— 之后批量生成不再轻易 OOM。
3. **值得做**：把"节点依次点亮 + 光点沿边传递 + 标签淡入"抽成一个 `mechanism()` 助手，
   HPA 轴/奖赏回路/生物钟都复用它，新机理分镜从 ~100 行降到 ~10 行。
4. **评估中**：用内置 `ImageGen`/`VideoGen` 对 1–2 个空镜做备选，比对观感与耗时后再决定。

## 六、给"下次开新片"的流程 checklist

- [ ] 先写 `timeline.json`（拍数即时长，BPM 锁定）→ `build_timeline.py` 生成 `timeline.js`
- [ ] 每个分镜先 `scene_preview.js <id> 5` 过一遍文字/时序，再进全片合成
- [ ] 生成底板前确认 `gpu_gate` 显存门槛通过（≥9GB 空闲）
- [ ] 机理动画优先复用模板，不要新写一套 SVG
- [ ] 全片合成只在"确认无误"后跑一次
