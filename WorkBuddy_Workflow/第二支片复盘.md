## 二、五个结构性失误

### 1. 分镜阶段没做「素材来源」决策（最大的一笔）

18 镜**全部默认走 AI 生成**，其中 7 镜（s6/s7/s9/s10/s11/s12/s14）是结构、几何、光效——
代码渲染 13 秒能做完，AI 花了 **3.9 小时**。

- **根因**：我沿用了上一支片的做法（全部 I2V），没有在分镜表里对每镜问一句"这个真的需要 AI 吗"
- **本该**：分镜表加一列「素材来源」，写分镜时就分流
- **代价**：3.9 小时 GPU + 这些镜头结构还不准（s6 三个半规管画成了交叉线框）

### 2. 提示词的物理错误，靠用户三次反馈才修好

s1 一个镜头改了 3 版，累计 84 分钟。三次都是同一个类型的问题：**提示词没有物理自检**。

| 版本 | 用户指出的问题 | 我的错误 |
|---|---|---|
| v1 | 颠簸太重、视角漂成前方路面 | 写了 `camera swaying with the suspension`、`Handheld shot` |
| v2 | 拐弯时窗外景物不变角度 | 只写"车在转弯"，没写转弯对画面的后果 |
| v3 | —— | 补上「视角/车姿/轨迹」三约束，才成立 |

- **根因**：我写提示词时只描述"看到什么"，没描述"物理上应该发生什么"
- **本该**：写完先过一遍「运动镜头三约束」清单
- **代价**：84 分钟 GPU + 三轮沟通

### 3. 队列能处理「慢」和「失败」，处理不了「卡死」

s8 提交后占着 ComfyUI 的 running 位 15.6 小时，`/history` 返回空、interrupt 无效，
**整条 GPU 队列（含别人 19 个任务）全被堵死**。

更糟的是我自己的安全阀：把"超时"判成系统性问题，**一次中止了剩下 5 个镜头**。

- **根因**：超时按"提交时刻"算，把 ComfyUI 排队时间也算进执行时间；且没区分"排队"与"卡死"
- **本该**：超时只在"任务已不在队列"时生效；卡死要单独识别（`/history` 空 + 长期占位 + interrupt 无效）
- **代价**：15.6 小时 + 重排 5 镜

### 4. 长驻服务挂在 agent 会话下

ComfyUI 由我的后台任务启动，会话一断就没了。第一次发生时白等一夜。

- **本该**：一开始就用独立进程（`.bat`）或 Windows 计划任务
- **代价**：一次夜间空转 + 一次重启排查（还被 ComfyTV 的批量删除触发沙箱拦截，卡了一轮）

### 5. 一个优化假设没验证就写进了文档

看到 WanGP 配置注释说"8 步三相位可减少慢动作效应"，我直接写进 SOP 当建议，
还花 16 分钟跑了实验版——结果是**扫描线撕裂 + 色边 + 破形**的废片。
根因是 `cfg=3.5` 对已蒸馏的 FP8 权重过猛。

- **本该**：任何"优化建议"写进文档前，先跑**单镜小样**验证
- **代价**：16 分钟 + 一条错误建议差点误导下一支片（已回改）

## 三、做对的四件事

1. **分层架构救了返工成本**。素材层 / 覆盖层 / 合成三层分离，改一镜的排版不用动素材，改一个素材不用重渲全片。s14/s17 的断字问题只花了 7 分钟重合成。
2. **断点续跑 + 磁盘兜底**。全程没有重复生成同一镜；s8 卡死那次也是靠"提交前先查磁盘/查队列"避免了二次提交。
3. **门控不抢占**。全程没调用过 `/interrupt`、没清过队列，别人的任务照常跑完——这是硬约束，守住了。
4. **每个结论都有实测数字**。耗时、时长误差、码率、音量、静止占比，全部有数，不靠"感觉差不多"。

## 四、工作流的六条结构性改动

前四条已写进 `视频制作通用流程.md`，后两条写进 Checklist。

### ① 分镜表加三列（把决策前移）

| 列 | 填什么 | 为什么前移 |
|---|---|---|
| **素材来源** | AI / 代码 / 实拍 | 决定这一镜要不要排 GPU 队列，影响总工期 |
| **物理约束** | 是否载具/运动镜头；相机是否刚性 | 写完提示词才发现要重写，代价是 30 分钟 |
| **预算** | 预计 GPU 分钟数 | 让"这支片要跑多久"在开工前就可知 |

### ② 关键路径原则：能离线的绝不排 GPU

GPU 是整条管线里**最贵、最不可控**的资源（要排队、会卡死、被别人占）。
凡是代码能渲染的、文案能写的、覆盖层能调的，都不该排在 GPU 后面等。

**推论**：GPU 任务应在**项目最早期**就提交排队，然后并行去写概念帧之外的活。
而不是"先生成完再写覆盖层"。

### ③ 验证纪律：假设先跑小样，再写文档

任何"这样会更好"的判断，在写进 SOP 之前必须有**单镜小样**或**最小复现**。
本片的 8 步采样、以及早期"用量化指标证明抖动减少"（指标本身失效），都是没做这一步。

### ④ 验收双轨：自动判据 + 人眼抽帧

自动判据只能抓数值（时长、静止占比、音量），**抓不到"断字""结构画错""构图难看"**。
本片 s14/s17 的换行孤字、s6 的半规管结构错误，全部是抽帧看出来的。

**要求**：成片至少抽 **2 轮 × 8~9 帧**，覆盖全部镜头，逐帧看文字可读性与结构正确性。

### ⑤ 长驻服务用独立进程

ComfyUI 这类服务不能用 agent 后台任务起。用 `.bat` 双击启动，或做成 Windows 计划任务。
会话结束不该影响它。

### ⑥ 返工成本表（决定"发现问题时该在哪一层修"）

| 层级 | 改一处的代价 | 什么时候发现最划算 |
|---|---|---|
| 分镜 / 文案 | 几分钟 | **最划算** |
| 概念帧 | 几分钟 | 划算 |
| 覆盖层排版 | 7 分钟（重合成） | 可接受 |
| 素材（AI 生成） | 25~30 分钟 | 贵 |
| 素材（代码渲染） | 13 秒 | 便宜 |
| 成片结构（镜数/节奏） | 全片重来 | **最贵** |

**结论**：所有能前移的检查都要前移。发现问题的层级越靠后，代价指数上升。

## 五、如果重做一次

同样的选题和分镜，按新流程走：

| 阶段 | 做法 | 预计 |
|---|---|---|
| 分镜 | 标注素材来源：11 镜 AI + 7 镜代码 | 30 分钟 |
| GPU 排队 | 11 镜一次性提交，约 5.8 h，**同时**去写覆盖层 | 后台跑 |
| 代码渲染 | 7 镜 Remotion，各 13 秒 | 2 分钟 |
| 覆盖层 | 18 镜文案与动画，与 GPU 并行 | 3 小时 |
| 底板 + 合成 | 各 15 / 7 分钟 | 25 分钟 |
| 质检 | 双轨，2 轮抽帧 | 1 小时 |
| **合计墙钟** | | **约 12~15 小时**（原 59 小时） |

**压缩的不是单镜速度，是等待与返工。**
