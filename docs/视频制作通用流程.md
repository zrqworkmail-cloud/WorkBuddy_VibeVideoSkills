# 视频制作通用流程 · SOP

> **定位**：这是「代码逐帧渲染」分支（**分支 A**）的完整方法论。
> 通用入口（五类视频的分流 + 跨分支共用的铁律）见技能 `WorkBuddy_Video_Workflow` 的 `SKILL.md`；本文是它背后最厚的那本手册。
> 适用于任何"画面由代码按时间计算出来"的视频——知识科普、数据解说、产品演示、纯动画短片，竖版横版皆可。
> 本文只写**方法与判据**，不绑定任何具体片子。项目实例参数见 [附录 A](#附录-a参考实现参数)。
> 姊妹文档：[《视频制作流程演进记录.md》](./视频制作流程演进记录.md) 记录为什么这么设计、改过什么、开源技能怎么选。

## 0. 适用边界

| | |
|---|---|
| ✅ **适用** | 画面元素位置/透明度/缩放都由时间函数决定的视频。文字动效、数据可视化、图形演示、AI 素材+文字叠加的解说片 |
| ⚠️ **部分适用** | 实拍素材 + 代码叠加层（分层思想、质检闸门、时间模型仍成立） |
| ↪️ **其他类型** | 真人口播 / 纯剪辑 / 图文轮播 → 见技能 `SKILL.md` 的 §5–§7 分支（本文的**时间模型、字幕规范、质检闸门、发布流程**仍通用） |

**核心判断**：如果你能说出"第 37.2 秒画面上有什么"，并且这个答案是算出来的而不是剪出来的，这套流程就适合你。

## 1. 七条核心原则

前四条管"怎么渲染"，后三条管"怎么安排生产"——后三条是第二支片复盘出来的，
它们不改画面质量，改的是**总工期**。

### 1.1 逐帧确定性渲染
所有动画是时间的**纯函数**：`render(lt)`、`FNS.sN(lt, t, el)`。给同一个 `lt`，永远得到同一帧。

**为什么**：任意一帧可复现、可定位、可对比。出问题能精确到"第 71.3 秒那帧文字压到了主体"，而不是"大概中间某处有点怪"。这是后面所有质检闸门的前提。

### 1.2 分层：素材层 / 覆盖层 / 音轨
- **素材层**：AI 生成、实拍、渲染出的背景视频
- **覆盖层**：文字、图表、图形（透明背景）
- **音轨**：BGM、配音

三层各自独立生成，最后一次性合成。改文案不用重生成素材，换素材不用动文案。

### 1.3 量化闸门，不靠"看着还行"
每个阶段有明确判据（时长误差 ≤0.06s、最长静止 ≤3s、音频电平 ≈-15dB）。**判据不达标就不进入下一步**，避免问题滚到成片才发现。

### 1.4 先找轮子，再造轮子
需要新能力时：搜 GitHub 找成熟开源项目 → 读它的文档和判据 → 装到本机 → **把它内部的量化标准变成你自己的质检标准**。这比从零设计快，而且拿到的判据是被别人验证过的。

### 1.5 关键路径：能离线的绝不排 GPU

GPU 是整条管线里**最贵、最不可控**的资源——要排队、会被别人占满、会卡死。

> 实测：一支 136 秒的片，墙钟 59 小时，其中**只有 16% 在真正生成**，
> 26% 被一次卡死堵掉，17% 在等别人用完卡。

**推论（按优先级）**：
1. 代码能渲染的镜头，**绝不排 GPU**（见 §3.0）
2. GPU 任务在**项目最早期**就提交排队，然后并行去写覆盖层 / 文案 / 概念帧之外的活
3. 不要把"等生成完"当成一个阶段——它是背景任务，不是串行步骤

### 1.6 假设先跑小样，再写进文档

任何"这样会更好"的判断（换采样器、换模型、换参数），在**写进 SOP 之前**必须有单镜小样或最小复现。

> 反面案例：照搬别人配置注释里的"8 步可减少慢动作"，直接写进文档当建议，
> 花 16 分钟跑出来是扫描线撕裂的废片。**没验证的建议比没有建议更危险**——
> 它会被下一支片当成既定经验执行。

### 1.7 验收双轨：自动判据 + 人眼抽帧

自动判据只能抓数值（时长、静止占比、音量、码率），**抓不到"断字""结构画错""构图难看"**。

> 实测：s14/s17 的换行孤字、s6 的半规结构错误，三道自动闸门全部通过，
> 全靠抽帧看出来的。

**要求**：成片至少抽 **2 轮 × 8~9 帧**，覆盖全部镜头，逐帧看文字可读性与结构正确性。

### 1.8 平台形态：信息密度决定留存

同样是"代码渲染知识视频"，为什么有的能上热门、有的 5 秒完播只有 15%？
差别不在渲染技术，在**信息密度**。

#### 参照：HyperFrames（HeyGen 开源，Apache 2.0）

口号 `Write HTML. Render video. Built for agents.`——和本管线**同构**：

| | HyperFrames | 本管线 |
|---|---|---|
| 时间轴 | HTML `data-start` / `data-duration` / `data-track-index` | HTML `data-t` / `data-anim` / `data-d` |
| 渲染 | Puppeteer 逐帧 seek + 截图 | Puppeteer 逐帧截图 |
| 编码 | FFmpeg | FFmpeg |
| 确定性 | 同输入同输出 | 同输入同输出 |
| 扩散模型 | **完全不用** | 本片用了 18 镜（错） |

它额外有的是：450 个现成区块组件（转场/标题/图表/地图/3D）、GSAP/Lottie/Three.js 适配器、
把生产流程注入 AI 的 Skills 机制。

**但它没有的东西才是关键：它没有任何"氛围镜头"。** 画面全是图表、几何、数据、文字动画。

#### 信息密度：热门科普片 vs 本片

| | 单镜时长 | 单位时间信息点 |
|---|---|---|
| 抖音热门知识类 | **1.5~3 秒**一个视觉变化 | 每 2 秒给一个新信息 |
| 本片（第二支） | **7.5 秒**一个镜头，一句文案 | 每 7.5 秒一个信息 |

**差 3~4 倍。** 这就是 5 秒完播 14.89% 的根因——不是画面不好看，是**前 5 秒没给够信息**。

「运气的形状」这类片子能火，因为它是概率的几何可视化：每一帧图形都在变，观众每 2 秒获得一次"哦原来是这样"。
而本片前 15 秒在讲"车一拐弯，你的胃先知道了"——**一句常识，配 7.5 秒风景**。

#### 由此产生的三条硬规则

1. **知识类短视频，单镜不超过 3 秒**（不是 12 秒）。>3 秒必须有持续事件，否则信息密度崩。
   —— 与 §5 第 1 步"无 >12s 长镜"是两个不同层级的约束：12 秒是**节奏缺陷**的红线，
   3 秒是**平台留存**的红线。
2. **反直觉结论必须在前 3 秒出现**。本片把"闭上眼反而更晕"放在第 15 秒，85% 的人等不到。
3. **画面亮度 ≥55/255**。本片全片 38~51（15~20%），手机信息流里读作"一块黑"。

> **一句话**：知识视频卖的是**单位时间的信息增量**，不是画面的精美度。
> AI 生成擅长做"好看的氛围"，恰恰是信息密度最低的那一类画面。

#### 开头两秒：用"第二人称钩子"，不要旁白铺垫

2 秒跳出率决定推流，而前两秒只有一句话的容量。**结构化句式**比自由发挥可靠：

| 环节 | 句式 | 作用 |
|---|---|---|
| 钩子 | 「明明只是……，怎么就……」 | 摆出观众的日常经验，制造"我也遇到过" |
| 反转 | 「这不是……，是……」 | 一句话给因果，把悬念在 3 秒内兑现 |
| 收尾 | 「愿你……」 | 从知识回到人，避免"讲完就断" |
| 系列化 | 「第 N 集｜系列名｜主题」+ 下集预告 | 同一批观众能被下一集接住 |

**长内容用"问题链"组织，不要写流水账。** 讲一个过程（历史事件、机制、案件）时，先列出观众会问的 3~4 个问题，每一幕回答一个；幕与幕之间是"回答上一问引出的下一问"，不是"然后……然后……"。完整版里内容多就**加镜头**，不要压缩时长——压时长会把因果链压断，观众只记住结论、记不住推理（平台版另剪，见下）。

#### 一题两剪：同一批素材，两条片子

既然"完整版"和"平台版"的要求冲突（前者要讲透，后者要抓人），就不要试图用一条片子兼顾。

| | 完整版 | 高密度版 |
|---|---|---|
| 时长 | 90~140s | **30~45s** |
| 单镜 | 7~8s | **2~3s** |
| 开头 | 铺垫、氛围 | **结论前置，第 0 帧就给反直觉** |
| 用途 | 合集沉淀、长视频平台 | 抖音信息流、投流测试 |

**成本极低**：素材、覆盖层框架、音轨全都复用，只需重排时间轴 + 重写文案 + 重渲。
实测一支 40 秒版从零到成片 **约 30 分钟、零 GPU**（`scripts/build_short.py`）。

> 关键手法：**从素材里切 2~3 秒片段**，不是把 7.5 秒镜头压缩——后者会变成快进，
> 观感是"赶时间"，不是"信息密"。

## 2. 开工前必须定的七个参数

这一步做错，后面全部返工。**先填这张表，再动手**。

| 参数 | 怎么定 | 常见取值 | 定错的代价 |
|---|---|---|---|
| **画幅与分辨率** | 按投放平台定。抖音/视频号/Reels → 竖版 9:16；B站/YouTube → 横版 16:9 | 1080×1920 / 1920×1080 | 改分辨率要重渲全部素材 |
| **帧率** | 与素材源一致。代码渲染 24/30 都行，**全片必须统一** | 24 / 25 / 30 | 混用会掉帧或抖动 |
| **总时长** | 信息量 ÷ 语速。一条主线讲完就停，不要凑 | 60–180s | 改时长 = 重排全部时间轴 |
| **节奏基准** | 有 BGM 用 BPM 卡点；无 BGM 用固定镜头时长（如每镜 3s） | BPM 90–130 / 镜头 2–5s | 中途改 BPM = 全片重排 |
| **镜头数** | 一个信息点一个镜头，宁多勿长（多镜头成本低，长镜头容易"静止超时"） | 10–30 镜 | 镜头数定太少会逼出长静止镜头 |
| **素材来源** | AI 生成（I2V/T2V）/ 实拍 / 纯图形（SVG·Canvas） | 按题材选 | 素材风格不统一，成片"拼盘感" |
| **音轨方案** | BGM 有无、是否配音、TTS 还是真人 | 纯 BGM / BGM+配音 | 音轨时长与视频不匹配，尾帧被裁 |

**BPM 怎么选**：信息密集 → 快（120–130）；叙事/情感 → 慢（85–100）。选定后 **每拍时长 = 60 / BPM**，这是全片唯一的时间单位。

## 3. 时间模型（一切对齐的基准）

### 3.1 唯一公式

```
镜头时长 = 该镜拍数 × 每拍时长
全片时长 = Σ 所有镜头拍数 × 每拍时长 = 音轨时长
```

**总拍数守恒**：这是全片最容易崩的地方。增删镜头、改某镜拍数，必须同步让总拍数回到设计值，否则音画错位。

### 3.2 三条铁律

1. **单一时间源**：所有时间从一份时间轴文件（timeline）派生。改完必须重新生成下游产物（如 json → js），不要手改生成物。
2. **拍数变了必须重建该镜素材**：素材是按旧时长裁切/定速的，拍数一改就错位。增量构建工具默认复用旧分段，必须显式指定重建列表。
3. **覆盖层按全局时间驱动，素材按拼接顺序对齐**：两边都只认时间轴，不要各自写死时间。

### 3.3 帧号与秒的换算

```
帧号 = round(秒 × 帧率)
```
所有抽帧、比对、定位都用帧号，避免浮点误差累积。

## 4. 工程分层（通用结构）

不要求文件名一致，但**职责必须分离**：

| 层 | 职责 | 产物 | 可替换性 |
|---|---|---|---|
| **时间轴** | 唯一时间真相：镜头、拍数、时长 | `timeline.json` + 生成物 | 不可替换，是地基 |
| **素材层** | 每镜的背景/主体画面 | 视频片段（mp4） | ✅ 可换 AI 模型、实拍、纯渲染 |
| **覆盖层** | 文字、图表、图形，透明背景 | 逐帧截图 → 视频 | ✅ 可换渲染引擎（Puppeteer/Canvas/SVG） |
| **音轨** | BGM、配音 | wav/mp3 | ✅ 可换 TTS、音源 |
| **合成** | 三层叠加出片 | 成片 mp4 | 逻辑固定，工具可换 |
| **质检** | 判据校验 | 报告 | 判据可调，位置不变 |

**建议目录**（参考实现采用）：

```
src/       时间轴、覆盖层源文件、概念帧
scripts/   构建与渲染脚本
out/       全部产物（不入版本库）
tools/     外部技能/素材参考
```

### 多片共存：共享脚本，不要分叉

做完第一支片、开第二支时，最容易犯的错是**复制一套脚本**。正确做法是"共享脚本 + 按片名路由"：

```
vibe-knowledge-video/
├── reference/
│   └── src/ scripts/ out/      ← 第一支片（不设 FILM 时默认用它）
└── films/
    └── <片名>/src|out/         ← 后续片子
```

脚本统一读环境变量 `FILM`：

```bash
python scripts/build_timeline.py                       # 第一支片
FILM=motion-sickness python scripts/build_timeline.py  # films/motion-sickness/
```

**为什么不能分叉**：脚本是**判据的载体**。分叉之后，每改一次质检逻辑要改两遍，两份必然逐渐不同步——那时"同一套标准"就不成立了，你会不知道自己看的报告是哪一版算的。

**代价**：所有脚本都要先改造一遍路径解析（一个十几行的共享模块就够），并且新增片名时必须带 `FILM` 前缀，漏了就会静默操作到第一支片上。这个坑要在改完的当天用两支片各跑一次验证。

## 5. 标准生产流程（八步）

每步都给了**判据**——不达标不往下走。

### 第 1 步 · 定节奏

写时间轴：每镜的 `id / 拍数 / 名称`。生成下游时间文件。

```bash
python scripts/build_timeline.py     # 输出节拍表
```

#### 1.1 分镜表必须同时定三件事（别等到生成阶段）

分镜表除了拍数，还要给每镜标三个字段。**这三个字段决定总工期，越晚定代价越大。**

| 字段 | 取值 | 影响什么 |
|---|---|---|
| **素材来源** | `AI` / `代码` / `实拍` | 要不要排 GPU 队列（见 §3.0） |
| **物理约束** | 是否载具/运动镜头；相机是否刚性 | 提示词写法（见 §3.2） |
| **预算** | 预计 GPU 分钟数 | 整支片的工期可预估 |

> **实测教训**：第二支片 18 镜全部默认走 AI，其中 7 镜本该代码渲染，
> 白花 3.9 小时 GPU，且结构还画错了（半规管画成交叉线框）。
> 这三个字段如果写在分镜表里，看一眼就能发现。

✔ **判据**：Σ 拍数 × 每拍 = 设计时长 = 音轨时长（误差 0）；每镜时长合理——**无 <1s 的碎片镜，无 >12s 的长镜**；
**每镜的三个字段都已填，且「素材来源」为 AI 的镜头已估算总 GPU 时长**。

> **为什么是 12 秒**：超过 12 秒的镜头，要维持"画面一直在变"就得往里塞大量动效；而覆盖层能加的动效面积有限（见第 7 节判据边界），塞到最后往往是"看起来在动、实际很闷"。
> 真需要长镜头时，素材层必须自带**持续事件**（人物走动、镜头推进、光效循环），不能靠覆盖层硬撑。

---

### 第 2 步 · 概念首帧

每个镜头画一张**静态首帧**，作为 AI 生成的首帧输入，也作为构图验收基准。

✔ **判据**：尺寸与素材层一致；主体位置符合构图意图（要"主体压下半"就在下半画）；一张图能说清这个镜头要表达什么。

> 概念帧是**最便宜的试错**：在这里改构图成本几乎为零，等生成完素材再改就贵了。

#### 2.1 媒介按题材选（选错必返工）

概念帧"粗糙 / 廉价"通常**不是细节不够，是媒介选错**。

| 题材 | 用什么 | 为什么 |
|---|---|---|
| 抽象机制图、图表、数据、流程 | SVG / HTML 画 | 构图精确可控、可参数化、改一版几秒 |
| 实景、解剖、光影、氛围 | **图像生成** | 材质、景深、次表面散射 SVG 画不出来 |

**廉价感三个来源**（一律避开）：① 高饱和 + 霓虹发光滤镜 ② 纯色块拼接、无材质无暗部层次 ③ 硬边几何（光柱像白棍、栅格像表格）。

SVG 版可以保留作**构图参考**，但不要当首帧喂给 I2V——模型会忠实继承它的"平"。

#### 2.2 概念帧提示词两条硬要求

- **抽象感受必须落在一个实物上**：写"闭眼后看到的黑暗"会得到全黑空画面；写"闭着的眼睛特写 + 眼睑透光"才成立。
- **解剖/器械类必须指定视角 + 部位名**：写"低角度看脑干"会得到岩石峡谷纹理；写 `inferior view + 脑干 + 小脑` 才认得出器官。

#### 2.3 批量出图后先看拼贴

单张 review 费 token，而且看不出风格漂移。把全部概念帧拼成一张总览（如 6×3），**一次性看风格一致性与明显失败帧**，比逐张看快一个数量级。

---

### 第 3 步 · 生成素材

用 I2V/T2V 模型从概念帧生成动态素材（也可用实拍/纯渲染替代）。

#### 3.0 先决定素材来源：**默认代码渲染，AI 只作例外**

**这一步做错，后面全是白工。** 一支片里往往一半镜头根本不该用 AI 生成。

> **默认规则（硬性）**：GPU 慢、要排队、会被别人占满、会卡死。
> 所以**能用代码渲染的一律用代码**，只有"代码确实做不出来"时才排 GPU 队列。
> 判断顺序是：**先问能不能代码做 → 不能 → 才用 AI**，不是反过来。

| 镜头类型 | 用什么 | 理由 |
|---|---|---|
| **结构 / 解剖 / 机械 / 图表 / 流程** | **代码渲染（Remotion / SVG）** ← 默认 | 几何关系本身就是信息，AI 只给"像那么回事"的近似；参数可精确控制、13 秒出片 |
| **抽象概念**：信号流、冲突、能量、光效 | **代码渲染** ← 默认 | 语义明确，AI 容易画成一团无意义的炫光 |
| **拟人 / 角色动画**：动物、人物动作、载具运动 | **代码渲染** ← 默认 | 骨骼 IK、轮系传动、循环动作，代码写出来是确定的（见下"鹈鹕测试"） |
| **实景**：真实人脸、车内实拍感、自然风光 | **AI 生成（I2V）** | 只有这一类代码确实做不出来——材质、次表面散射、景深、真实光影 |

**一句话判据**：
- 「这一镜**必须看起来像真的**吗？」→ 不必须 → **代码**
- 「必须是真实质感的实景吗？」→ 是 → **AI**

**"鹈鹕测试"就是这条规则的最好证明**：
Simon Willison 用一句 `Generate an SVG of a pelican riding a bicycle, with animation` 做模型基准，
模型直接写出 SVG 路径 + 动画，浏览器渲染——**零视频生成模型**。
车轮自转、踏板圆周、腿的 IK 跟随、身体起伏、背景滚动与轮速匹配，全部是数学。
参考实现见 `remotion/src/PelicanBike.tsx`，1080×1080 / 24fps / 5 秒，**渲染 15 秒**。

**代价对比（实测）**：

| | AI 生成 | 代码渲染 |
|---|---|---|
| 单镜耗时 | 25~30 分钟（GPU，要排队） | **13~15 秒**（CPU，随时跑） |
| 改一版 | 整镜重生成，再等半小时 | 改参数重渲，十几秒 |
| 可控性 | 提示词说"三个环"，它给四个 | 几就是几 |
| 首次编写成本 | 无（写提示词） | 10~20 分钟（组件可复用） |

> 参考实现 `remotion/`：s6「三个半规管」用 SVG 画三条管从前庭发出、各自成环，
> 渲染 13 秒；同一镜 AI 生成花了 28 分钟，且生成出的三环是交叉细线框，
> 观众数不出"三个"——**结构类镜头 AI 的失败方式不是糊，是"似是而非"**。

**典型误判**：以为"AI 生成的更精致所以更好"。精致 ≠ 准确。
科普片里结构画错的代价，比画面朴素大得多。

#### 3.1 提示词四查

1. **细节充分**——主体材质、光线、环境写具体，否则模型给糊的
2. **契合叙事功能**——这个镜头在讲什么，画面就要服务什么
3. **与概念帧同向**——首帧已定的构图不要被提示词推翻
4. **与其他镜头区分**——相邻镜头视觉上要能区分，否则观感"一坨"

**必带运动**：不要写 "completely still"。写慢眨眼、呼吸、光效明灭、极缓推近。**静止素材必然触发节奏缺陷**（见第 7 节闸门②）。

#### 3.2 运动镜头的三条物理约束（载具/跟拍必查）

凡是车、船、飞行、手持跟拍这类**载具镜头**，只写"车在转弯"是不够的——模型不知道转弯对画面意味着什么，会退化成横向平移。必须显式交代三件事：

| 约束 | 要写清什么 | 只写表面会怎样 |
|---|---|---|
| **视角** | 相机相对载具的朝向（如"垂直于行进方向的真侧视"），并排除错误视角 | 只写 side window → 漂成前方路面视角 |
| **车姿** | 姿态变化**对窗外画面的后果**：横滚→地平线倾斜几度；偏航→景物通过角度持续变化 | 只写 "car leans into a curve"，不写后果 → 违和 |
| **轨迹** | 载具方向沿道路切线；景物通过角度**不是固定一个角度** | 全程 `streak past horizontally` = 假设永远直行 |

外加两条：
- **相机刚性固定**：`rigidly locked to the cabin, no handheld shake, no bumps, only a faint high-frequency engine vibration`。写 `swaying with the suspension` 就是**主动要求颠簸**。
- **车内固定参照物**：窗框、头枕、座椅剪影相对镜头不动——这是让观众读懂"外面在动"的锚点。

还要防构图事故：路面和护栏要**贴近画面下部**，路侧地面与路面齐平。画得太远、露出下坠坡面，观感就是"车要飞出悬崖"。

#### 3.3 负面词必须随题材重审

负面词和正向提示词一样**带题材假设**。上一支片的负面词含 `cgi / 3d render / illustration / bioluminescence`（为压插画感），但换成解剖题材时，内耳/脑干/神经元**本来就是发光半透明的医学渲染**，这几个词会与首帧直接对抗，把结构抹掉或拉灰。

做法：拆成 `neg_base`（只压瑕疵与解剖错误，全片共用）+ 按镜头类型的额外套（实景套加反插画词，解剖套不加），按镜头路由。

#### 3.4 采样器选择：先排除"慢动作效应"

Lightning 4 步蒸馏有明显**运动迟缓**倾向：画面会动，但动得黏滞，该转向的地方只做平移。**这不是提示词能解决的**。

| 方案 | 结构 | 实测结论 |
|---|---|---|
| **4 步（默认）** | HIGH(0→50%) → LOW(50→100%)，全程 cfg=1 | **可用**。快，静态/微观/载具镜头都用它 |
| 8 步三相位 | HIGH+cfg3.5(0→25%) → HIGH+cfg1(25→50%) → LOW+cfg1(50→100%) | **本地 FP8 权重上不可用**（见下） |

⚠️ **8 步三相位实测失败，不要直接上**：

设想来自 WanGP 的 `Lightning i2v 3 Phases - 8 Steps` 配置（作者原话是想"减少加速 LoRA 的慢动作效应"），
但在本地 `wan22EnhancedLightning_v2I2VFP8HIGH/LOW` 上跑出来是**坏的**：

- 水平扫描线撕裂，贯穿整个画面
- 青/橙互补色边（过饱和）
- 窗框等硬边结构直接破形

根因：开头那段 `cfg=3.5` 对**已经蒸馏过的 FP8 权重**过猛，把潜变量推出分布。
慢动作没解决，先出了伪影。

**判据修正**：
1. 运动"黏"时，**先怀疑提示词**（见 §3.2 运动镜头三约束），这是本片验证有效的路径
2. 真要试 8 步，**必须先跑单镜小样**，只渲染 1 镜确认无伪影再批量
3. 试 8 步的代价是耗时翻倍且可能全废，**默认不要开**

#### 3.5 无人值守生成：队列设计三条铁律

素材生成动辄几十分钟一镜，实际都要挂机跑。这类队列最容易出的不是崩溃，而是**静默错**——任务被判失败其实还在跑，或者已经跑完又被重提交一遍。

**先有时间预算**：同模型同分辨率下单镜耗时应落在稳定区间，但**这个区间随 GPU 争用浮动很大**——参考实现 704×1280×121 帧，独占 GPU 约 17 分钟，被别的进程抢卡则 25–36 分钟甚至翻倍。所以基线要记成"独占 / 争用"两档，估总时长和定超时上限（≥2× 争用值）都按坏的一档算。按"几分钟一镜"排计划，必然排到半夜还没跑完。

| 铁律 | 做法 |
|---|---|
| **排队 ≠ 执行** | 超时只算"正在执行"的时间。每轮轮询先查任务是否仍在队列，在就续期；排队等待不计入超时 |
| **判失败前先查磁盘** | 只有「不在队列 + 没成功 + 没落盘」才算真失败。直接重试 = 同一条 GPU 活干两遍 |
| **提交前先查队列和共享输出目录** | 门控等待期间任务可能已跑完并从队列消失。提交前查同镜任务（有就接管轮询）、查输出目录（有就直接取回） |

另外三条：
- **安全阀只抓系统性错误**：首镜即失败 → 判模型名/节点/版本错误、中止整批是对的；但**"超时""队列消失"不算系统性**，继续下一镜。
- **断点续跑**：产物存在且大小合理即跳过，中途被 kill 重跑能接上。
- **偶发 `execution_error` 直接重试**：单镜报执行错误不等于参数/模型有问题，实测重试一次即过。先重试再动提示词，别把偶发当系统错误去改配置。
- **绝不抢占**：只过 GPU 门控排队等，不调 `interrupt`、不清别人的队列。抢占换来的是一边浪费别人的算力，一边污染自己的产物。

✔ **判据**：帧数与时长符合预期；**帧间运动能量 > 阈值**（用质检脚本同款算法算，别靠眼睛看）。

#### 3.6 卡死 ≠ 慢：先分清再处置

队列长时间不动时，第一反应常是"GPU 慢/在排队"。**慢和卡死是两件事，处置完全相反**：慢只需等，卡死要重启服务。按下面三条判：

| 判据 | 说明 |
|---|---|
| 长时间占 running 首位却无产出 | 正常单镜耗时是稳定区间，超过 2~3 倍仍无产物就不正常 |
| `/history/<pid>` 返回**空** | 既没 success 也没 error——不是失败，是执行线程已挂 |
| `POST /interrupt` 返回 200 但队列无变化 | 线程不响应中断，等下去不会自愈 |

**卡死比"自己慢"严重得多**：它占着显存不放，后面排队的任务（**包括别人的**）会一起被堵死，且堵多久无法预估。三条判据同时成立就立即处置，不要继续等。

处置顺序：停掉自己的队列 → 重启服务（**沿用原启动参数**，否则显存/精度配置会变）→ 确认显存回落到基线 → 重新排队未完成的镜头。

⚠️ 重启会清空队列，**共享 GPU 上别人的任务会一起丢**——这是破坏性操作，必须先征得同意，不能自作主张。

⚠️ **重启起来的服务要能脱离当前会话存活。** 用会话内后台任务启动的常驻服务，会话一结束就被回收，队列会再次静止，而且这次没有任何报错——过几小时才发现又是白等。所以：把完整启动命令（含 `--reserve-vram` 这类显存参数）写进文档，交给独立于会话的进程托管；下次接手先确认服务"活着"（能查队列、显存有占用），再排查别的原因。

⚠️ **进程秒退、但服务日志干净 → 先怀疑被宿主安全策略杀掉，别去改配置。** 典型触发：自定义节点启动时要**批量清理历史备份/缓存**（几十上百个文件），被宿主的批量删除保护直接终止进程，标记只留在宿主侧，ComfyUI 自己的日志里一个字都没有——很容易误判成"参数写错了"。处置：把那个目录**改名旁置**（不删，占几 MB），让它无旧文件可清即可正常启动；这类目录会随时间重新堆积，**每次重启都可能复现**，属已知项，不必重新排查。

### 第 4 步 · 建素材层

把原始素材处理成"时长精确等于时间轴要求"的片段：

- **裁头尾**：AI 生成的开头常有画风过渡，尾部常有多余动作，都要裁
- **定速**：速度即表演。要慢的段落放慢，要快的加速
- **调色/特效**：统一全片影调，避免每镜风格打架
- **构图微调**：个别镜头裁切/位移，给文字腾出安全区
- **慢放必须插帧**：`setpts` 放慢 + `minterpolate(mci)` 补帧，**绝不**用 `fps` 复制帧（会变幻灯片）

✔ **判据**：每段时长 vs 时间轴期望，误差 ≤0.06s；全部段落齐了才拼接；拼接后总时长与时间轴一致（**总长要单独验，逐段合格不等于总长合格，见 4.3**）。

#### 4.1 两种构建器：按镜长分布选

| 情况 | 用哪个 | 为什么 |
|---|---|---|
| 镜长跨度大（7~18s 混排），需逐镜裁切/分段定速/改构图 | 异构版 `build_base.py` | 每镜参数不同，靠配置表驱动 |
| 所有镜长都贴着素材原生（如全部 14~15 拍 ≈7.5~8.0s） | 均匀版 `build_base_uniform.py` | 只需四步：裁头 → 重定时 → 补帧 → 统一调色；逻辑简单、不易出错 |

**均匀版的收益**：镜头时长贴着素材原生，几乎不需要慢放 → 运动能量不被摊薄 → 闸门②从"事后抢救"变"事前达标"。
参考实现里 18 镜 × 14~15 拍，全部落在 1.0~1.2 倍速区间；对比第一支片的 2.4 倍慢放，运动质感差一个量级。

#### 4.2 时长对齐的三个坑（ffmpeg）

时长必须**精确到帧**，否则全片音画错位。三个实测踩过的坑：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 用 `-t` 裁时长 | 短 0.09~0.10s | `-t` 按输出时间轴裁，补帧后末帧时间戳不在 target 上。改**按帧数裁**：`tpad=stop_mode=clone` 补足 + `trim=end_frame=N` |
| 末尾再加 `-r 24` | 多 2 帧（179→181） | 补帧后流已是 24fps，再 `-r` 会重复帧。删掉 `-r` |
| 裁头后时长又偏 | +0.065~0.114s | `trim=start=` 打乱时间戳，容器按末帧 PTS 算时长。末尾用 `setpts=N/(24*TB)` 强行对齐网格 |

**裁头是必须的**：I2V 前 0.5~1.5 秒通常还在从概念首帧"过渡"，画面发糊。参考实现取 0.9s，裁掉后靠倍率补足目标时长（7.56s 裁 0.9s 剩 6.66s，凑 7.48s → 1.12 倍慢放，可接受）。

#### 4.3 分段取整必须按累计边界，否则误差会累加

**逐段合格 ≠ 总长合格**，这是最容易漏的一条：每段误差都远小于容差（如 0.01~0.02s），十几段加起来就能漂出 0.3s，超出全片容差 0.06s 好几倍，音轨和画面就错位了。

根因是每段**各自**做 `round(target × fps)`，每次都往同一个方向取整，误差单调累积。

正确做法是**按累计时间取整**，让误差只落在最后一段：

```
cum += target                     # 累计目标时长（秒，不取整）
n_end   = round(cum * fps)        # 累计边界帧号
n_frames = n_end - prev_n         # 本段帧数 = 边界差
prev_n  = n_end
```

这样 Σ 各段帧数恒等于 `round(总时长 × fps)`，总长误差从"段数 × 单段误差"降到半帧以内。

→ 建完底板先算一遍：`Σ段帧数 == round(总时长×fps)`，成立才继续；不成立说明还在逐段取整。
→ 这条同样适用于任何"按镜切段再拼接"的管线（覆盖层分段渲染、音频切片），只要是独立取整就一定会漂。

### 第 5 步 · 做覆盖层

在覆盖层主文件里为每镜写内容与动画：

- **入场**：`data-t`（相对本镜起点的秒）+ 动画类型 + 时长
- **逐帧逻辑**：需要精确控制时写时间函数 `FNS.sN(lt, t, el)`
- **卡点光效**：跟拍点触发的闪光/缩放

**动手前两件事**（都踩过坑）：
1. **先看这一镜的底板长什么样**，再决定文字放哪。素材层有亮区（人脸/发光物体/窗帘）时，文字要么加底衬，要么错位到暗处——这个决定做在前面，比合成后返工便宜得多。
2. **单镜样式用 `#sN` 限定**。改 `.txt`、`.h1` 这类全局类会波及全片所有镜头。

**遵守第 6 节的七条硬规则**，违反必出 bug。

#### 5.1 覆盖层框架：新片新建，别抄旧片

旧片的 `render` 往往与它自己的场景结构强耦合（硬编码 `.s3head`、`.s7head` 这类按镜号起的类名），照抄过来会把旧片的构图假设一起带进来，改一版比新写还慢。**可复用的是驱动模型，不是代码**：

- **元素级声明式驱动**：`data-t`（本镜相对秒）+ `data-anim`（rise/fall/scale/pop/left/right/blur/fade）+ `data-d`（时长），逐帧由统一的 `render(t)` 计算
- **只有声明式表达不了的特殊效果**才写 `FNS.sN(lt,t,el)`

这样九成镜头只改 HTML 属性、不碰 JS；动画逻辑集中在一个 `render` 里，改全局节奏不会漏镜头。

#### 5.2 透明模式：URL 参数只是开关，样式还得自己加

`?ov=1` 这类参数是**信号**，不是行为——样式仍要在脚本里给 `html`/`body` 加上透明类（如 `.ov{background:transparent}`）。漏了这步，页面底色仍是 `#000`，截图带黑底，叠到底板上会把素材**整帧盖掉**：表现就是"预览里只有文字、背景全黑"。

**预览干等超时先查依赖，别查排版**：预览靠 `window.TIMELINE` 就绪后置位 `__ready` 再截图。忘了引入时间轴脚本 → `TIMELINE` 为空 → `__ready` 永不置位 → 预览白等超时。超时报错时先看脚本加载与就绪标志，不要先怀疑动画代码。

#### 5.3 构图基线：先按画幅定三条水平线

换画幅**不是缩放，是重排版式**。开工前把三条基线定死，之后所有元素都往这三条线上挂：

| 画幅 | 地平线 | 字幕带 | 版式分区 |
|---|---|---|---|
| **横版 16:9**（1920×1080，默认） | y ≈ 760~800 | y ≈ 880~1040 | 左巨字字牌 + 右条目卡；纪年条改**右上横排胶囊** |
| 竖版 9:16（1080×1920） | 中部偏下 | 下三分之一 | 竖排纪年条贴侧边；信息自上而下堆叠 |

- **别把竖版的"上下堆叠"直接搬到横版**——会得到左右两片空白。宽画幅要么把信息分列（左牌右卡），要么让场景横向铺满（行军、驿马、城门）。
- 竖排元素（纪年条、竖排标题）在横版里显突兀，改横排胶囊贴角。
- 附录 A 那套数值是竖版的，横版要重算；改画幅后先渲一镜确认三条线，再批量做其余镜头。

**字幕统一走一个组件，不要逐镜手摆。** 字幕是唯一"每镜都出现"的元素，样式分散写必然逐渐不一致，也最容易压到主体：

- **底部安全区**：字幕带以下留 ~300px，避免被平台 UI 压住（横版对应 y 880~1040）。
- **渐变底板**：字幕块自带"透明 → 深色"的渐变底，比纯描边更抗亮背景（配合「文字可读性」那节）。
- **入场**：整块上移 ~90px + `easeOut` 淡入，时长按拍对齐；不要逐字弹，字多的句子会显得碎。
- **主体让位**：画面主体限制在字幕带之上（横版 **y < 780**），**严禁与字幕重叠**。这一条是"主体压字幕"的唯一防线——自动判据测不到。

> ⚠️ **y<840 不够，实测要压到 780**（2026-10 陈桥片）。840 只是"不压字幕底板"，但人物头顶、道具顶端、标题下沿仍会探进字幕带上沿，观众看到的就是"字幕糊在画面里"。780 是留出「字幕上移入场动画」的 90px 位移量之后的安全线。
> 落地方式：**出片前用正则扫源码**里所有 `y= / cy= / baseY=` 落在 780–1080 的元素，逐个核对是"背景"（山脊、地面、地毯，可以进）还是"正文"（人物、道具、文字，必须挪）。人眼在 1000+ 帧里一定会漏，扫描不会。

**贯穿全片的量做成角落常驻角标。** 进度、倒计时、累计数这类"全片只有一个值"的指标，放在主容器里由**全局帧号**驱动（不是按镜头重算），位置固定在角上（如右上），观众随时能读到当前进度。按镜头各写一份，必然在切镜处跳变。

#### 5.4 视觉风格：插画感剪影 + 丰富动效

"扁平简笔"是最省事、也最容易被判"丑"的一档——它省掉材质与光，只剩形状，于是所有画面都长得像 PPT 图表。基线应是**插画感剪影**：

| 层次 | 做法 |
|---|---|
| 场景 | 剪影化的多层景（山脊/城墙/人群），靠**层次**而不是细节立住 |
| 运动 | 多层**视差**（远慢近快）；角色做步行/奔跑**循环**；环境光随时间**渐变**（黄昏→夜→黎明用 RGB 插值，别切色块） |
| 戏剧动效 | 关键节点给"大动作"：数字砸屏 + 镜头抖动、牌位连环倒、披袍（`scaleY` 从肩到脚）、光芒放射、盖章 |
| 质感 | 墨色 × 鎏金一类的双色体系；纪年条做"史料感"锚点 |

**判据**：随便截一帧，应该看得出"这是个场景"，而不是"这是几个色块"。做不到是缺层次与光，不是缺细节。

**"插进去 / 穿过去"用分层遮挡，不用 mask。** 钥匙入锁、箭入甲、刀入鞘这类动作，观感的关键是"进入的部分被表面挡住"。`mask` 只能挖洞或露出，做不出这个层次；正确做法是把表面拆成前后两半，后半画在物件之下、前半画在物件之上，各自用 `clipPath` 裁一半，物件平移时自然被前半盖住。

**"反应型"动效的起点绑事件帧，不绑场景起始帧。** 涟漪、烟尘、火光、震波这类"由某个动作引发"的效果，只要在动作完成之前就开始渲染，观众看到的就是"还没插进去就泛起波纹"。做法是把起算点写成**事件完成帧**（物件到位的那一帧，如 `f >= 70` 才开始画），而不是"镜头起点 + 一个大概的偏移"。

**扩散类动效的半径按对角线算，确保出屏。** 波纹/冲击环的终点半径靠目测给，最常见的失败是"扩散到画面边上停住"，像被裁掉。半径至少取到**屏幕半对角线**（1920×1080 约 1100px），曲线用 `easeOut`（先快后慢才像水波，匀速像机械光圈），线宽与透明度随进度衰减（如线宽 `5→1.4`、`opacity = min(1,p*8)*(1-p)*0.5`）——不衰减的环收尾时是一道硬边。

**历史题材的标牌是考据点，不是装饰。** 匾额、门额、横排题字按古制**自右向左**、用繁体；写成现代横排，懂的人一眼看出，前面所有的画面质感都白搭。

#### 5.5 人物：身份化造型 + 三段式手臂

人物是"丑"的主要来源，也是最容易反复返工的部分。三条硬规则：

| 规则 | 反例（会被退回） | 正例 |
|---|---|---|
| **按身份区分造型**，不要一套通用小人 | 皇帝、将军、士兵长得一模一样，只换颜色 | 君主=冕冠+垂旒+龙纹团花；将军=盔缨+护肩；士兵=盔+甲+矛；文官=**展脚幞头**（两侧长翅）+笏板；幼帝=总角双髻+短袍；平民=布巾 |
| **手臂必须三段式实体** | 一根直线从肩连到手，抬起来像"僵尸"；或者干脆只画两个圆点当手 | 肩→肘→手两段关节 + 袖身（宽于手臂）+ 袖口 + 椭圆手掌；后臂画在躯干之后、前臂画在之前，任何姿势都能看出结构 |
| **姿态用预设，不靠单参数** | 所有"举手"都用同一个 `armUp` 角度 | `idle` / `raise`（**45° 斜上振臂**）/ `cup`（上臂下垂 + 前臂折向胸前持杯）。直臂上举一律禁止 |

**运动细节**：站立时给呼吸（±1.2px 正弦），行走时给腿部相位差 + 手臂反向摆动；`walk` 参数**不传就不该动**——传 `undefined` 却仍按 `f` 算摆动，会让站着的人腿一直在抖（踩过，返工一轮）。

**死亡/失势的表现**：用**人物褪色 + 红叉划掉 + 死因同步出现**，不要用光环、升天光柱这类西式符号——历史题材里符号错了比画得糙更刺眼。

**身份/处境转变用"两个形象交叉淡化"，不要在一个形象上改参数。** 加冕、换装、升格这类时刻，观众要看的是"变了"这个动作本身：先渲染旧形象（如 `general`），再渲染新形象（如 `emperor`），在同一位置按进度交叉 `opacity`，重叠的几帧就是"黄袍加身"的过程。改同一个组件的颜色/配饰参数只会得到一次突兀的跳变，而且会把该组件的分支逻辑写成一堆 `if`。

### 第 7 步 · 合成

逐帧截取覆盖层 → 与素材层叠加 → 混入音轨 → 出片。

```bash
node scripts/composite.js <帧率>
```

✔ **判据**：帧数 = 时长 × 帧率；`ffprobe` 音视频时长一致；文件大小在合理区间。

> **时间预算**：逐帧截图 + 编码的吞吐约 **8fps**（1080×1920），2 分钟片约 7 分钟出片。**合成从来不是瓶颈**——真正的黑洞是素材生成（§5 3.4）。所以别为"省合成时间"去砍质检、砍抽帧，那省的是分钟，赔的是重做。

> **注意**：混音时**不要加 `-shortest`**，它会裁掉尾帧。

#### 7.1 工具链：用自带的二进制，别等系统装

有三个"看起来必须装、其实不用装"的东西。装一遍花的时间，远少于踩错入口浪费的轮次。

| 项 | 结论 |
|---|---|
| **ffmpeg** | 系统里没有也能跑：`imageio-ffmpeg` 自带一份静态二进制，`get_ffmpeg_exe()` 取路径。抽帧 / 混流 / `volumedetect` 全够用，装一次覆盖整条链路 |
| **无头浏览器** | 不必另装 Chrome：直接指到 Playwright 已下载的 Chromium（`CHROME_EXECUTABLE_PATH`），并显式设 `CHROME_HEADLESS=true` |
| **Remotion CLI** | 入口是 `./node_modules/.bin/remotion`。用 `node node_modules/@remotion/cli/dist/index.js render …` 会**退出码 0、什么也不产出**——最坏的一种失败：脚本看起来成功了 |
| **输出路径** | 一律写**相对 cwd** 的路径（`out/x.mp4`）。绝对路径 / `/tmp` 在 Git Bash 下映射异常，文件会落到意料之外的地方 |

⚠️ "退出码 0 却没产物"这类失败没有任何报错可查，唯一防线是**渲染完立刻 stat 输出文件**。判据里"帧数 = 时长 × 帧率"就是干这个的——别只看进程返回值。

#### 7.2 音轨：用既定曲目，不要为每支片现合成

BGM 不是"每片配一段"，它是**账号的听感资产**：观众靠低频重心、节奏密度认得出这是你的片。每支片临时合成一段，等于每片都从零建立辨识度。

| 做法 | 为什么 |
|---|---|
| **优先做成与母版等长** | 母版自带的收尾就是成片的收尾，不用猜淡出起点、不用硬切——比"截取 + 补淡出"干净一档 |
| 维护一份**母版**（完整曲目），每片按成片时长**截取前 N 秒** | 同源才保证听感一致；截取不需要重新作曲 |
| 尾部补 `afade=t=out` | 截断点大概率落在乐句中间，硬切会"咯噔"一下 |
| 混流用 `-t <成片时长>` 精确截断 | 见上方"不要 `-shortest`" |
| 编码留 `volume=-1dB` 余量 | 目标 mean ≈ -15dB、峰值不触顶（闸门③） |

**成片比母版长，就做无缝循环，不要硬接。** 完整版动辄 200s 以上，母版只有 130s 量级，直接 `-stream_loop` 拼接会在接点"断一下"——母版尾部本来带淡出，接回去等于淡出完又突然满音量。做法：

1. **裁掉母版尾部的淡出段**（保留到淡出起点，别把淡出也一起循环）
2. 首尾各取 **2~4s** 做**交叉淡化**，得到一条"首尾相接听不出缝"的循环环；淡化曲线必须**等功率**（`sqrt(1-t)` / `sqrt(t)` 加权），线性权重在中点会掉 ~3dB——听感正是"接点处音量塌一下"，RMS 曲线上看是一个凹坑
3. 用这个环铺满目标时长，**最后 3s 单独淡出**
4. 验收看**循环点附近的 RMS 曲线**：应当连续平滑、无凹陷（实测 −11~−17dB 连续），只看总电平是发现不了接点的

**事件音效可以纯代码合成，不必找素材。** 马蹄、战鼓、开城轰鸣、钟声这类短音效，用振荡器 + 包络（numpy 就够，如 `gen_sfx.py`）比翻素材库快得多。要点两条：**按画面事件对齐**（事件落在哪一拍就落在哪一拍，与覆盖层共用同一份时间轴，别手记秒数）；**混音给 BGM 之上留一层**、权重约 0.55，`amix` 之后**重新过一遍闸门③**——音效会把峰值顶高，只验 BGM 那一条必然漏。

**定顺序：先看母版有多长，再定内容量。** 能讲满就用满（母版自带淡出，天然收尾）；只讲得了一半，才退回"截取 + 尾部 `afade`"。反过来先定时长再找音乐，必然要么硬切、要么淡出点落在乐句中间——两种都听得出来。

#### 循环听起来还是"重来一遍"？改用「延长剪辑」

循环法的天花板就在这里：**只要在循环，就一定会回到起点**。观众听到的是"这段旋律我好像刚听过"，而不是"接缝不自然"。当片子时长超过母版 1.5 倍时，别再优化接缝了，换方法：

1. 原曲**完整播到 E**（E 要避开尾部淡出段）
2. 在 E 附近取 4s，用**等功率交叉**接到曲中的**相似段 S**
3. 之后自然续播到目标时长

S 怎么找：在主体区间内枚举起点/终点（都按小节对齐，BPM 用 onset 能量通量自相关测），用 24 个频带的能量向量算**余弦相似度**，取最高分。实测能到 **0.9998**——这个精度下 4s 融合完全听不出来。

**融合时长要跟着相似度走，不是固定值。** 相似度 >0.999 时，几十毫秒（如 40ms）等功率融合就够——两段波形本来就几乎重合，融合越长越像"两段同时在响"，反而糊；只有相似度掉到 0.99 以下才需要 2~4s 慢慢过渡。做**首尾环**（循环法）时两段是曲子的不同位置，才一律按 2~4s 给。判据：融合段越长、越要确认两段频谱不是"两个声部"。

**全片只留一个融合点**，这是和循环法最本质的差别：循环法每 N 秒就"重新起手"一次，延长剪辑只有一处，且落在相似段落上。

验收（两条都要看，只看 RMS 会漏）：
- 接续区 0.5s 窗 RMS 相邻跳变 **< 4dB**（正常音乐起伏范围）
- 频谱跳变 **< 1.4× 全片均值**（和普通乐句过渡同量级）

反面教材（都踩过）：`-stream_loop` 硬接（断点明显）；2s 长交叉等于**把开头播了两遍**，接缝掉到 −27dB；循环点落在**前奏淡入段**，每轮都"重新起手"。

**要"听"音频时，给客观画像而不是形容词**：解码成 `f32le` raw 落盘再用 numpy 分析（子进程里传相对路径不可靠），输出低频能量占比、频谱质心、BPM、首尾淡入淡出、峰值电平。这些能回答"是不是同一个东西、有没有削波"，但**"好不好听"必须人耳**——不要替用户下这个结论。

#### 8.1 发布物料：封面与文案同样是"算"出来的

成片过闸门只是"能播"，投放前还有一层物料。这一层最容易出两类错：**素材取错源**、**合规漏标**。

| 项 | 做法 | 为什么 |
|---|---|---|
| **封面** | 写成 HTML 版式，宽高与底图走 URL 参数（如 `?w=&h=&bg=`），一套模板渲出竖版/横版；宽 > 高时自动切横版布局；出图用渲染器的**单帧命令**（如 `remotion still`），与成片共用同一套组件 | 按平台各做一版必然逐渐不一致；参数化后改版式只改一处；另起一套封面工具链，会慢慢和成片风格分叉 |
| **平台封面规格** | 抖音要**两套**：横封面 **4:3**（1440×1080，信息流展示）+ 竖封面 **3:4**（1080×1440，个人主页）；成片的 16:9 在这两处都用不上 | 直接拿 16:9 上传，平台自动裁左右，标题常被切掉一半 |
| **封面底图** | 从**素材层**（`base` 分段）抽帧 | 成片已烧入覆盖层文字与标签，抽出来的帧带文字残影，会和封面新加的字叠在一起 |
| **章节时间码** | 按「第几拍 × 每拍时长」从时间轴换算 | 手记秒数必然与画面错位；节奏一改更难对。这是"单一时间源"的延伸 |
| **AI 标注** | 画面含 AI 生成内容时，按平台要求标注"内容由 AI 生成" | 只勾"原创"不标注，有限流/下架风险；标注不损失什么，漏标代价很高 |

**封面图形的两条硬要求**（2026-10 陈桥片实测）：

| 要求 | 反例 | 正例 |
|---|---|---|
| **主视觉必须一眼能辨认出是什么** | 用几段直线围出上窄下宽的梯形当"黄袍"，远看是个罐子 | 画出**肩 → 两宽袖 → 下摆 → 腰带**的 T 形轮廓，袖口有厚度、交领有 V 口 |
| **光效用同心环，不用粗放射条** | 8 道 30px 宽的三角放射光，在深底上叠出灰褐色，像玻璃裂纹 | 3 圈同心细金环（r 递增、opacity 0.13→0.06）+ 径向柔光渐变 |

图形类主视觉还有个通用检查：**缩小到手机缩略图尺寸（约 200px 宽）还能认出来吗**。封面在信息流里就是这个尺寸，看不清等于没画。

✔ **判据**：封面与成片视觉一致（同一版式体系、无文字重影）；章节点逐条跳转能对上画面；平台必填项（AI 声明、合集、话题）齐备。

#### 8.2 上传：半自动填表，发布键留给人

平台（抖音等）**没有对个人开放的内容发布 API**。只能走网页，但网页流程可以半自动化：

| 环节 | 谁做 | 怎么做 |
|---|---|---|
| 登录 | **人** | 扫码。脚本用固定 profile，登录一次后续免扫 |
| 上传视频 | 脚本 | `input[type=file]` 直接 `uploadFile()` |
| 标题 / 简介 / 话题 | 脚本 | 点输入框 → 逐字输入 |
| 封面 | 脚本（**需真实点击**） | 上传图片走 `setInputFiles` 即可；但弹窗里的「保存」必须用 Playwright 真实 `locator.click()`——合成 MouseEvent 会被 React 静默忽略，封面会存成视频首帧（黑场） |
| 自主声明 / 合集 | **人** | 选项列表因账号而异，脚本猜不准 |
| **点发布** | **人** | 最终发布权必须在人手里 |

参考实现：`scripts/douyin_upload.js`（上传 + 填标题简介，不点发布）。

**四个必须知道的坑**：

| 坑 | 现象 | 修法 |
|---|---|---|
| 扫码登录后跳首页 | 脚本在上传页等不到 `input[type=file]`，白等几分钟 | 找不到控件就重新 `goto(上传页)` |
| `domcontentloaded` 太早 | 控件还没挂载 | 用 `networkidle2` + 等 3.5s |
| **话题上限 5 个** | 写 7 个会弹「最多可添加5个话题」，可能卡发布 | 文案阶段就控制在 5 个 |
| **脚本退出会关掉浏览器** | 填好的表单全丢（踩过一次，白做一轮） | 结尾 `setInterval(()=>{}, 1<<30)` 常驻，别让进程退出 |
| **封面「保存」用合成事件** | 弹窗确实关了，但封面变成视频第 0 帧（黑场），右侧预览还是空白 | 必须 `locator.click()` 真实点击。`dispatchEvent(new MouseEvent('click'))` React 不响应，**且不报错**——这类"静默失败"只能靠截图对比发现 |
| **话题写成纯文本** | 描述里 `#历史` 只是普通文字，不变成蓝色话题 chip，等于没打标签 | 必须**键盘输入** `#话题名` 触发下拉，再点 `div[class*="tag-hash"]` 里 `startsWith` 匹配的那一项；`execCommand('insertText')` 不会触发下拉 |

> 为什么不做全自动：登录态接管 + 自动发布违反平台规则，账号有被限流风险。
> **半自动的边界很清楚——机械的复制粘贴交给脚本，身份与发布权留给人。**

#### 8.3 数据回流：看「2 秒跳出率」，别看播放量

发布后第一件事是读数，但**播放量是被推荐量决定的，不是内容质量的信号**。真正该看的是留存曲线的最左端。

| 指标 | 说明 | 为什么用它 |
|---|---|---|
| **2 秒跳出率** | 点进来 2 秒内划走的比例 | **最早、最灵敏**。它只反映"封面承诺 + 第一帧"是否成立 |
| 5 秒完播率 | 撑过 5 秒的比例 | 反映钩子，但比 2 秒滞后 |
| 完播率 | 看完的比例 | 对 60 秒以上的片子意义有限 |

**实测基线（同账号三支片）**：2 秒跳出率 **45%~50%**——一半人两秒内就走。

✔ **判据**：
- 改版后 2 秒跳出率 **降到 30% 以下** → 钩子改造有效
- 仍在 **45% 左右** → 前两秒还是没抓住人，问题在选题或封面承诺
- **不要发布后立刻读数**：冷启动推流的前 30 分钟波动极大，等 2 小时再看

> 数据不好时先别改画面。按「选题 → 封面承诺 → 前两秒 → 信息密度」的顺序排查，
> 越靠前的问题，改起来越便宜。

## 6. 七条硬规则（渲染五条 + 工程两条）

违反任何一条都会出难查的 bug。这七条与题材无关，**任何代码渲染视频都成立**。
前五条管"动画怎么算"，后两条管"改动波及谁、元素怎么摆"——后两条是实战里踩出来的。

### 规则 1 · 禁止 CSS transition / keyframes
逐帧 seek 时，transition 的中间态不可控，画面会抖。
→ 所有动画由时间函数计算：`opacity = f(lt)`，而不是 `transition: opacity .3s`。

### 规则 2 · 禁止 `Math.random()`
每帧重算会得到不同随机值，元素会跳。
→ 用确定性伪随机：`rng(seed)`，同一 seed 永远同一序列。

### 规则 3 · 禁止 `background-clip: text`
无头浏览器合成层会丢失渐变填充，**文字直接变透明**（看起来像"字消失了"，极易误判为动画 bug）。
→ 用纯色 + `text-shadow` 光晕模拟渐变感。

### 规则 4 · 带样式的原子标签不可拆字
给文字加了渐变/描边/特殊字体的标签，如果被逐字拆分动画，样式会丢失、字会消失。
→ 需要逐字动画时，**样式挂在每个字上**，或整块做动画不拆字。

### 规则 5 · 慢放素材必须同步压缩动画时间
视频放慢 K 倍后，画面动作的实际时刻变了。如果动画仍按原时间轴走，就会出现"水滴还没落下，文字已经出现"。
→ 在该镜时间函数首行 `lt /= K`，把本地时间压回设计时刻表，动作落点重新对齐。

### 规则 6 · 改全局样式必须限定到当前镜头

覆盖层通常"一个类服务所有镜头"（`.txt`、`.h1`、`.note`）。直接改这些类的定位，会同时移动全片每一个镜头。

→ 单镜微调用 `#sN .txt{...}` 限定作用域。
→ 只有"全片都该这样变"的属性才动全局（如统一加强描边）。

**判断标准**：这次改动是"这一镜特殊"还是"全片都该这样"。前者必须带 `#sN`。
**踩过的坑**：想给 s8 的文字块下移，差点直接改 `.txt{bottom}` —— 那会让其余 13 镜的文字全部移位。

### 规则 7 · 绝对定位块必须算垂直占位，不能靠目测

同一 section 里常有多个 `position:absolute` 的块（数据组、图表、文字块）。它们的 `top`/`bottom` 各写各的，很容易叠在一起——而**重叠在缩略图上往往看不出来**，只有成片才刺眼。

→ 排完版做一次占位核算：列出每个块的 `top` 与 `top+高度`，确认无交叠。
→ 文字块尤其危险：高度随内容变（标题行数 + 术语卡 + 注释），不能只看首行位置。

**踩过的坑**：s8 的额度条在 828px，文字块顶部约 860px，只差 32px；叠加后发现标签与标题首行贴死，得再挪一次。

### 规则 8 · 改组件内部变量后，立刻全局搜旧名

重写一个共用组件（人物、道具、场景）时，最容易漏的是**别处还在引用它的局部变量**。

**踩过的坑**：把 `Person` 的手臂从 `L/R/LY` 改成三段式关节后，文官手里的笏板还写着 `x={R - 2} y={LY - 26}`——渲染到第 792 帧才抛 `ReferenceError: R is not defined`，前面 700 多帧完全正常，第一反应会以为是"那一幕有问题"，白查半天。

→ 改完组件立刻 `grep -n "\bL\b\|\bR\b\|\bLY\b" src/`（或对应旧变量名），确认没有残留。
→ **小样渲染不能替代这一步**：`--frames=0-12` 只覆盖开头，崩溃帧在 792，小样照样通过。真正的保险是 grep。
→ 崩溃定位靠渲染日志里的 `An error occurred while rendering frame N`，拿到 N 再回源码找那一幕用到的组件。

## 7. 三道质检闸门

| 闸门 | 时机 | 工具 | 判据 |
|---|---|---|---|
| **⓪ 素材粗筛** | 每出一镜（生成完立刻） | `qc_clip.py` | 无明显冻结/空镜。**只能抓粗差**，见下方局限 |
| **① 单镜** | 每次改画面 | 单镜预览（**必须叠真底板**） | 无 JS 报错；排版不压主体；**文字与底板亮部对比度足够**；时序与动作对得上 |
| **② 节奏** | 合成后 | 节奏体检（**低阈值均值差**，判"真实冻结"） | **最长连续冻结 ≤3.0s**；静止占比 >45% 需检查 |
| **③ 成片** | 交付前 | ffprobe + 像素统计 | 音画时长误差 ≤0.06s；关键帧特征符合预期；音频 mean ≈-15dB 且峰值不触顶 |

**判据为什么是这些值**：来自开源项目 `anything2explainer`（★2.7k）的量化标准，经实践验证——最长静止超过 3 秒，观众就开始划走。

**闸门②的静止判定**：逐帧算「与前一帧的平均灰度差」，低于 **0.002 灰度**（约 0.5/255）即记为一帧冻结，取**最长连续冻结时长**作判据。素材慢漂移（如呼吸）不算运动，别被它骗过——这也是第 3 步要求"必带运动"的原因。

⚠️ **两代度量各有一个坑，问题通常出在阈值而不在度量本身**：均值差配 1.5/255 这种"看起来很宽"的阈值时，深色底 + 局部小动画会被大片静止区稀释成假阳性；占比法配 0.3% 时，**大面积缓慢微摆**（单像素变化不到 6 灰度）会被判成冻结，是假阴性。结论：默认用**均值差 + 足够低的阈值（0.002 量级）**，占比法只留作交叉验证——见下方「判据在测什么」。

### 闸门⓪ 的局限：别把粗筛当验收

**为什么要有它**：闸门②跑的是成片，要等 18 镜全齐、底板拼好、覆盖层渲完才能做。那时才发现某镜"入场即停"，重做一镜又是半小时。⓪ 把检查前移到"素材到即检"。

**但它对 AI 生成素材偏宽松**：生成模型自带时间噪声，帧间差异永远大于阈值（实测各镜平均能量是阈值的 13~45 倍），"静止"几乎不可能被触发。所以它**只能抓明显冻结/空镜**，真正的静止风险出现在后期慢放之后——**闸门②仍必须在成片上跑**。

**别用码率判断动静**：文件小不等于画面静。暗调、细节少的镜头码率天然低（实测同长同分辨率下 2.6MB ~ 7.4MB 相差三倍），要判动静只能算帧间差异。

### 闸门① 之前：先确认预览工具本身可信

**这是整套流程里最容易骗人的一环。** 单镜预览如果没把素材层真正叠上，你看到的"干净画面"就是假的——排版看起来完美，成片里文字全压在亮背景上。

**踩过的坑**：预览脚本给 `body` 设了不透明底色，截图时把底板整帧盖掉。连续几轮预览都显示"没问题"，直到合成才看见 s8 的文字压在三个浅色液体柱上。

→ **工具自检法**：挑一个你**确定应该出现**的底板特征（某镜的柱子/人脸/星空），预览里必须能看见它。看不见 = 叠加链路断了，先修工具再改画面。
→ 预览脚本里任何"为了好看"设的底色/背景，都会破坏透明叠加，一律不要加。

### 文字可读性：被忽略的第四道判据

文字和素材层是分开做的，所以"文字压亮部"只有合成后才暴露。这类问题在成片里最刺眼，但**所有自动判据都测不到**（帧间能量、时长、电平都不管对比度）。

→ 设计文字位置时就要看底板亮度，而不是等合成后再调。
→ 素材层有大片亮区（人脸、发光柱体、窗帘、天空）时，文字必须二选一：**加底衬**（scrim / 深色卡片）或**错位**到暗区。
→ 底衬的强度按背景亮度定：背景越亮，底衬 alpha 越高、模糊越大。

### 排版：先算单行容量，别让长句掉出孤字行

同一类"自动判据测不到、只有抽帧才看得见"的缺陷，还有**折行**。

- 中文全角字符约等于 1em，所以**单行可容纳字数 ≈ 容器宽 ÷ 字号**（留 5% 余量）。72px 字号配 900px 容器，最多约 12 个字。
- 超了不会报错，只会把末尾两三个字挤成单独一行——观感很刺眼，而帧间能量、时长、电平、甚至对比度判据全都不管换行，**只能靠抽帧看**。
- 修法优先级：**降一级字号**（h2→h3，保留层级对比）> 拆成两句 > 收窄内边距。长句本来就属于信息密度高的那一档，降一级往往更合层级，比硬塞更省事。
- 排完版做一次**字数核算**：逐行算「字数 ÷ 字号」，超过「容器宽 ÷ 字号」的直接标记重排，别等合成后靠眼睛抓。
- **字数会变的元素要自适应字号**：印章、字牌、标签这类容器固定的元素，字数在 2~6 之间浮动，字号写死就会出现"两字撑满、六字溢出"。按「容器宽 ÷ 字数 × 系数」算，或按字数分档——这是同一类"不报错、只在成片里刺眼"的缺陷。

### 改完之后：用差分证明"只改了该改的地方"

改一处文字（删一个词、换一个标签）后，肉眼对比两版成片几乎不可能；而"整体看着没坏"也不等于"别处没被波及"。可靠的办法是**帧级差分**：

1. 取**改前 / 改后同一帧号**的帧（按帧号，别按文件名猜）
2. 转灰度逐像素相减，统计**差异像素总量**
3. **逐行扫描**差异带，看差异集中在哪几行——应正好落在被改元素的位置
4. 设一个**对照区**（画面中部、或未改动的其他镜头），应当 **0% 变化**

判据：**差异像素量与被改文字面积同量级**，且无关区域零变化。差异远大于文字面积 → 有连带位移；差异为零 → 改动没生效（常见于改了没重渲，或改的是没被引用的那份文件）。

⚠️ 取区域前先确认元素的**实际定位**：按 CSS 里写的 `bottom` 反推 y 坐标经常算错——先扫全图找差异带，再读它的坐标。

> 这条路子也是**没有视觉能力时的兜底**：读不了图，但像素统计照样能回答"改动生效了吗、波及别处了吗"。

### 出片前：三项自检（渲染完成后、交付前）

自动闸门只验"有没有动、时长对不对"，验不到"画面上有没有不该有的东西"。渲染完先跑这三项，再谈交付：

| 自检 | 做法 | 抓什么 |
|---|---|---|
| **空白帧扫描** | 每 ~12s 抽一帧，算方差与主色块数 | 漏渲 / 透明层没叠上的**全黑或纯色帧**。方差≈0 即异常；刻意的起幅黑场要单列说明，别一起算进异常 |
| **元文字未上屏** | 在源码里搜"机制说明、系列标签、制作标注"这类词，逐条确认没被渲进画面 | 草稿期写给人看的字跟着上了屏——图表机制说明、"第 N 集"标签是高频漏项 |
| **逐幕坐标求交** | 列出每一幕所有文字块的 `x / y / 宽 / 高` 区间，两两求交 | 跨块重叠：图例压地名、角标压标题。规则 7 的"同 section 占位核算"抓不到这种情况 |

✔ **判据**：三项零命中；或命中项能逐条说明"设计如此"。

> 这一层是**给自己做的**，不是给闸门做的。三项都是"数值全绿、画面有错"的那一类——自动判据天生看不见它们。

### 判据在测什么（决定你能怎么改）

**第一步是选对度量，不是调阈值。** 同样是"帧间差异"，两种算法会给出相反结论：

| 度量 | 算法 | 失效方式 |
|---|---|---|
| 全帧平均灰度差（阈值 1.5/255） | 下采样灰度图，逐帧求全画面平均绝对差 | **阈值太高**：深色背景 + 局部小动画（滚动条、数字计数、盖章）时均值差 <1.5/255，把活镜头判成 3 秒以上静止（假阳性） |
| **全帧平均灰度差（阈值 0.002）**（默认） | 同上，阈值压到 ~0.5/255，取最长连续冻结时长 | 对真正的极慢漂移仍不敏感（那本来也不算"事件"）；阈值必须按片校准，别跨片照搬 |
| 变化像素占比（单像素 >6 灰度，阈值 ~0.3%） | 统计"变"的像素占比 | **阈值太高**：大面积缓慢微摆逐帧位移小、单像素变化不到 6 灰度，被判冻结（假阴性）；适合抓"有没有事件"，不适合判"有没有在动" |

深色底的片子几乎必然踩第一条：画面整体是黑的、局部在动，均值被大片静止区稀释。**但把阈值压到 0.002 后，同一个度量就恢复了**——这说明当年该改的是阈值，不是换度量。换成占比法虽然救回了深色底，却把"缓慢微摆"推进了坑里（大面积慢移推不动 0.3%）。**判据用"最长连续冻结 ≤3s"这个说法，比"静止占比"稳**：前者只关心连续多久没变化，后者会把全片零散的静止帧加总，读起来像缺陷但其实无害。

**第二步是记住它只测"有没有变化"**，不测"变化好不好看"：

- **小元素推不动判据**：r=8 的光点即使动起来，占屏面积也远低于阈值。实测给光点加四段尾迹后，静止占比只降 2 个百分点。
- **要推动判据，必须用"硬边缘 + 高对比"的变化**：判据先把画面下采样（分析尺度常在 270px 宽量级），**柔光呼吸、渐变明暗这类软过渡会被采样直接抹平**——像素差低于 6 灰度阈值，数值上是零运动，人眼却觉得"在呼吸"。这就是**伪运动**，拿它救静止判据是白做。
- 有效的三类：**画面实体的硬边动作**（旗帜、火苗、狼烟、驿马、宫灯、蒸汽——边界锐利、逐帧位移 ≥2px）、**高对比长线条**扫过（指针、旗面）、**大面积高幅度**位移（不是低幅度呼吸）。
- ⚠️ **别用抽象背景粒子"点点"凑运动**：它推得动判据，但观感廉价，用户会直接判"背景在飘"。运动要长在**画面里存在的东西**上——把"满屏余烬"换成旗/火/烟/马之后，静止帧同样归零，质感却完全不同。判据只认变化量，不认这变化是否合理，**这条只能靠人判断**。
- **幅度要与分析尺度匹配**：慢速微摆（<1px/帧）在 270px 量级的下采样尺度下等于没动，数值上就是静止。要么把幅度加到 ≥2px/帧，要么换成一个真正的实体动作。
- **判据通过 ≠ 观感好**：花哨但廉价的运动能轻松过闸门，同时毁掉质感。
- **判据不通过 ≠ 一定难看**：设计性的定格（如收尾镜的静止）本来就该静。

**第三步：任何单一数值指标都必须与人眼抽帧交叉验证。** 指标说"通过"，抽帧看是不是真在动；指标说"静止"，抽帧看是不是真有变化。换度量或换阈值之后要**重跑一支老片校准**，别把旧阈值直接搬过来。

**质检脚本别把画幅写死**：分辨率从 `ffmpeg -i` 的输出正则解析，横竖版共用同一套判据。写死 1080×1920 的脚本换横版后会**静默算错分区**（亮度分区、字幕带位置全偏），而报告照样显示"通过"。

**正确用法**：判据用来**发现你漏掉的死角**（"这镜居然 12 秒没变化"），不是用来刷分。发现之后先问"为什么这么久没变化"，答案通常是**镜头太长**或**素材本身是静态的**——那要改结构，不是加特效。

## 8. 踩坑速查（症状 → 根因 → 规则）

| 症状 | 根因 | 规则 |
|---|---|---|
| 字"消失"或变透明 | `background-clip:text` 在合成层丢填充 | 纯色 + text-shadow 光晕 |
| 慢放变幻灯片 | 用 `fps` 复制帧 | `setpts` + `minterpolate(mci)` |
| 拼接后总长被压缩 | 多段转场塞进一条 filtergraph，offset 错位 | 分步拼接，每步校验时长 |
| `-ss/-to` 裁出来的时长不对 | 参数放在 `-i` 之后被当成输出限制 | 输入侧裁剪，放 `-i` 之前 |
| 生成时 OOM | 外部进程瞬时占显存，只看利用率% 会误判 | 用**空闲显存**硬门槛，不看利用率 |
| 误判"两个进程抢端口" | 虚拟环境的 python 与启动器是**父子进程=同一服务** | 查 ParentProcessId 再下结论 |
| 后台任务莫名消失 | shell 里加 `&`，随 shell 退出被连坐 | 用托管后台任务机制 |
| 成片某块"很黑" | 覆盖层有专用压暗渐变（scrim），**设计如此** | 与未加 scrim 的素材对比会误判，勿"修" |
| 慢推镜头加了没效果 | 参考值是"镜头级"速率（5%/1.5s），被拉长到整镜（20 倍时长） | 镜头级用，或直接换素材 |
| 周期性光效验证为"无差异" | 跨拍抽帧被素材慢漂移混淆 | 抽**同拍相邻帧**对比 |
| 单镜时长与时间轴错位 | 改了拍数却复用旧素材分段 | 改拍数必须重建该镜 |
| 改完时间轴后画面全错 | 忘了重新生成下游时间文件 | 生成物不可手改，必须重跑构建 |
| **预览显示"排版完美"，成片里文字压背景** | 预览脚本给 body 设了不透明底色，底板被整帧盖掉 | 预览必须保持透明；用已知底板特征自检 |
| **透明模式预览只有文字、背景全黑** | 只加了 `?ov=1` 参数，没在脚本里给 html/body 加透明类，底色仍是 `#000` | 参数只是开关，样式必须同时改；自检看底板特征 |
| **单镜预览干等超时、控制台无报错** | 时间轴脚本没引入 → `window.TIMELINE` 为空 → `__ready` 永不置位 | 超时先查脚本加载与就绪标志，别先改动画 |
| **队列十几小时无产出，任务仍占 running** | 执行线程已挂（`/history` 空、`interrupt` 无效），不是排队慢 | 三条判据确认后重启服务；卡死会堵死整条共享队列（§5 3.5） |
| **重启后队列又静止，且毫无报错** | 服务是会话内后台任务启动的，会话结束进程被回收 | 长跑服务脱离会话启动；启动命令写进文档，接手先探活（§5 3.5） |
| **覆盖层照抄旧片，改一镜要动一堆硬编码类名** | 旧片 render 与它自己的场景结构强耦合 | 只复用驱动模型（`data-t/data-anim/data-d`），代码新建（§5 5.1） |
| **文字压在亮部看不清，而所有自动判据都通过** | 文字与素材层分开开发，对比度不在任何判据里 | 排版前先看底板亮度；亮区加底衬或错位 |
| **加了一堆小动效，静止占比只降 2 个百分点** | 判据算全画面平均差，小元素贡献 <0.0005 | 用大面积/高对比变化；或改镜头长度 |
| **改一处样式，全片镜头都移位** | 直接改了服务所有镜头的全局类 | 单镜改动必须 `#sN` 限定 |
| **两个块叠在一起，缩略图看不出来** | 多个 absolute 块各写 top/bottom，没算垂直占位 | 排完版做一次占位核算 |
| **单镜 17 秒，怎么加动效都"闷"** | 镜头本身太长，素材又是静态的 | 超过约 12s 必须配"持续事件"，或缩短镜头 |
| **车内镜头颠得厉害，但公路是平的** | 提示词写了 `camera swaying with the suspension` / `handheld` | 相机写 **rigidly locked to the cabin**，只留极轻微高频振动 |
| **拐弯时窗外景物只平移、不变角度** | 只写"车在转弯"，没写转弯对窗外画面的后果 | 见 §5 第 3 步「运动镜头的三条物理约束」 |
| **转弯镜头"像车要飞出悬崖"** | 路面/护栏画得太远，露出下坠坡面 | 路面与护栏贴近画面下部，地面与路面齐平 |
| **运动黏滞，该转向的地方只做平移** | Lightning 4 步蒸馏 LoRA 的慢动作效应 | 换 8 步三相位采样，别先怀疑提示词 |
| **负向提示词与首帧打架** | 负面词带题材假设（解剖片不能用 `cgi/3d render/bioluminescence`） | 换题材必须重审负面词，按镜头类型分套 |
| **生成成功却被判超时、重复提交** | 轮询上限 < 真实执行时间（显存吃紧时可达 60 分） | 上限 ≥2× 预期；**超时先查磁盘，不重试** |
| **磁盘兜底取到别的片的同名素材** | 输出目录多片共享，`s7_*.mp4` 重名 | 兜底按「前缀 + 提交时间」双过滤 |
| **批量出图后才发现某镜糊了** | 没做素材级粗筛，等成片才暴露 | 每出一镜立刻跑 `qc_clip.py` |
| **扫码登录后自动化脚本卡住** | 登录成功会跳创作者首页，不在上传页 | 找不到控件就重新 `goto(上传页)` |
| **填好的表单突然全丢** | 脚本进程退出，puppeteer 把浏览器一起关了 | 结尾 `setInterval` 常驻，别让进程退出 |
| **话题标签被平台拦** | 平台上限 5 个 | 文案阶段就控制在 5 个 |
| **刚发布就看数据，误判** | 冷启动推流前 30 分钟波动极大 | 等 2 小时再读，主看 2 秒跳出率 |
| **文件小就以为画面静** | 暗调/低细节镜码率天然低，与运动量无关 | 判动静只能算帧间差异，别看码率 |
| **概念帧"看着粗糙"** | 媒介选错：实景/解剖题材用 SVG 硬画 | 抽象机制用 SVG，实景/解剖/光影用图像生成（§5 第 2 步） |
| **SVG 引线渲染成黑三角** | 开放路径 `<path d="M… L…">` 默认 `fill:black`，被当闭合路径填充 | 引线/折线一律显式 `fill="none"` |
| **模糊元素周围出现硬边方框** | 滤镜区域默认只有对象 bbox 的 120%，模糊半径远大于对象时被裁切 | 小尺寸元素别套大 `stdDeviation`，或先扩大滤镜区域 |
| **无人值守队列首镜超时，整批中止** | 安全阀把"排队超时"误判成模型/节点错误 | 只有"提交即失败"才算系统性错误；超时/队列消失继续下一镜 |
| **同一镜被提交两次，GPU 白跑一遍** | 门控等待期间任务已跑完并从队列消失 | 提交前查队列与共享输出目录，有就接管轮询或直接取回 |
| **上次踩的坑这次又踩了** | SOP 有用户级与仓库两份副本，只改了一份，加载到的是旧版 | 改完用户级立刻同步仓库副本，推前 `diff` 一次（§12 ④） |
| **照旧结论绕开 `git push`，历史反而乱** | 旧环境"代理拦截 git 传输"的结论未随环境更新 | 先探通道再下结论；拦截确实存在时走 API，但必须复刻 SHA（§12 ②） |
| **每段时长都合格，拼接后总长却差 0.3s** | 各段独立 `round(时长×fps)`，取整误差同向累加；单段容差盖不住 | 按**累计边界**取整，Σ段帧数 = `round(总时长×fps)`（§5 4.3） |
| **长句末尾两三个字单独占一行** | 字数 × 字号 > 容器宽；超了不报错，只会折行 | 单行字数 ≈ 容器宽 ÷ 字号；超了降一级字号或拆句，只能抽帧发现 |
| **重启服务时进程秒退，服务日志却干净** | 节点启动要批量清理历史备份，被宿主批量删除保护直接杀掉，标记只在宿主侧 | 查宿主安全策略；把该目录**改名旁置**而非删除（§5 3.5） |
| **偶发执行错误被当成配置问题** | 把单次 `execution_error` 当系统性错误，去改模型/参数 | 先原样重试一次（实测即过），再怀疑配置（§5 3.4） |
| **封面上的字和底图上的字叠在一起** | 封面底图从**成片**抽帧，而成片已烧入覆盖层文字/标签 | 底图只能从素材层（`base` 分段）抽（§5 8.1） |
| **发布后被判非原创 / 限流** | 画面为 AI 生成，却只勾"原创"、没标"内容由 AI 生成" | 按平台要求标注 AI 生成；封面/文案与成片同批交付（§5 8.1） |
| **深色底的活镜头被判"静止 3 秒以上"** | 静止检测用全帧平均灰度差，**阈值又给到 1.5/255**，大片静止区把局部动画的均值稀释掉了 | 同一个度量把阈值压到 **0.002 灰度**即可（别急着换度量）；并与抽帧交叉验证（§7） |
| **渲染脚本退出码 0，却一个文件都没产出** | 用 `node node_modules/@remotion/cli/dist/index.js` 调 CLI，入口不对时会静默成功 | 入口用 `./node_modules/.bin/remotion`；渲染完必须 stat 产物，别只看返回值（§5 7.1） |
| **质检报告"全部通过"，其实一项都没算** | 短版时间轴 `beats=0`，时长按 `beats×beatSec` 算成 0，判据分母为空 | 时长优先取显式 `dur`；判据脚本要校验输入完整性，别把"没算"当"通过" |
| **每支片的 BGM 听感都不一样** | 为每片临时合成新曲，低频重心与节奏密度都在漂 | 用既定**母版**按片长截取 + 尾部淡出，不现合成（§5 7.2） |
| **音频切片报 `slice indices must be integers`** | 用累加浮点当数组索引（`start += 0.5`） | 累加后立刻 `int()`，或直接用帧号算边界 |
| **改一处文字，无法确认有没有波及别处** | 两版成片肉眼对比不可行，"看着没坏"不等于没波及 | 同帧号灰度差分 + 逐行扫描定位差异带，差异量 ≈ 改动面积、无关区 0%（§7） |
| **编译报 `symbol already declared`** | 同一文件里复用的小图形与导出组件**同名**（`const Mirror` vs `export const Mirror`） | 局部图形一律改名加后缀（`MirrorPanel`）；导出名保留给真正的场景组件 |
| **复用旧组件时编译报"属性不存在"** | 按记忆给它传了未定义的 prop（如 `opacity`），TS/JSX 直接失败 | 复用前先看组件的 props 签名，别凭印象传参 |
| **渲染到某一帧突然 `ReferenceError`，前面全正常** | 增删/重写场景时漏了组件引用，只有该镜首次出现的那帧才求值 | 改完先渲**前 12 帧小样**（`--frames=0-12`），或按崩溃帧号 grep 渲染日志 |
| **加了柔光呼吸/渐变，静止判据一点没降** | 下采样后软过渡被抹平，像素差 <6 灰度 → **伪运动** | 环境动效要用**画面实体**的硬边高对比动作（旗/火/烟/马），别用柔光呼吸（§7） |
| **印章放两个字撑爆、四个字空一半** | 容器固定、字号写死，字数一变比例就崩 | 字号按字数自适应（或分档），别给固定 px（§7 排版） |
| **换横版后分区判据全偏，报告却显示通过** | 质检脚本把分辨率写死成竖版尺寸，裁剪坐标仍按旧画幅算 | 分辨率从 `ffmpeg -i` 正则解析，横竖共用一套判据（§7） |
| **缓慢微摆的镜头被判"冻结"，抽帧看明明在动** | 判据用「变化像素占比 0.3%」，大面积慢移逐帧位移小、单像素变化不到 6 灰度 | 改用**低阈值均值差**（<0.002 灰度记冻结），判"最长连续冻结 ≤3s"；占比法只作交叉验证（§7） |
| **满屏粒子在飘，被判"背景在动"** | 用抽象背景粒子凑运动量，推得动判据但观感廉价 | 运动要长在**画面实体**上（旗/火/烟/马/灯/蒸汽），不用背景点点（§7） |
| **循环 BGM 在接点"断一下"** | `-stream_loop` 硬接母版，尾部淡出后突然满音量 | 裁掉尾淡出 → 2~4s 首尾交叉淡化做环 → 铺满 → 片尾 3s 淡出（§5 7.2） |
| **循环做了，接点处仍"音量塌一下"** | 交叉淡化用**线性**权重，两段不相关信号在中点各半，功率掉 ~3dB | 淡化用**等功率**曲线（`sqrt`）；验收看循环点 RMS 有无凹坑，不看总电平（§5 7.2） |
| **加了音效后成片峰值削波** | 只验了 BGM 电平，音效叠加把峰值顶上去 | 音效层混完**重新过闸门③**；权重约 0.55，别与 BGM 抢（§5 7.2） |
| **字幕被平台 UI 压住，或压到画面主体** | 字幕逐镜手摆，没有统一安全区 | 字幕走统一组件：底部 ~300px 安全区 + 渐变底板 + 上移入场；主体限制 **y<780**（840 只够避开底板，头顶仍会探进字幕带，§5 5.3） |
| **不该上屏的草稿文字出现在画面里** | 图表机制说明、"第 N 集"这类给人看的标注留在渲染树里 | 出片前搜元文字逐条确认未上屏（§7 出片前自检） |
| **图例压住地名，读成一串** | 只做了同 section 占位核算，没做跨块求交 | 逐幕列文字块坐标两两求交；地图类图例与地名**分置**（§7 出片前自检） |
| **"插进去"的动作看着像贴在表面** | 用 `mask` 挖洞表现插入：mask 只能"挖掉/露出"，做不出"被表面挡住"的层次 | 把表面拆成**前后两半**（后半在物件之下、前半在物件之上），各自 `clipPath` 裁一半；插进去的部分自然被前半遮住（§5 5.4） |
| **古代匾额/横排标牌写成现代从左到右** | 默认套了现代阅读顺序，繁简也没换 | 古制横排**自右向左**、用繁体（"開"在右"封"在左）；这类考据错一眼被看出来（§5 5.4） |
| **重命名/移动大目录一律 `Permission denied`** | 不是权限问题，是有进程持有句柄（渲染器/预览服务/编辑器），杀进程后仍可能被资源管理器、索引服务占着 | 用 `robocopy /E /MOVE` 整目录搬运（源目录自动删除），比反复重试 `mv`/`Move` 可靠（§12 ④） |
| **改了目录结构，几百 MB 产物突然待提交** | 忽略规则写成 `/out/`，前导斜杠把它锚死在仓库根那一层 | 写 `out/`（匹配任意深度）；改完用 `git check-ignore -v <路径>` 验证（§12 ⑤） |
| **迁移后某天脚本静默读写到旧目录** | 只搬了文件，文档/脚本/技能里的路径引用没全改 | 迁移当天全仓 grep 旧目录名一次改完，漏一处不报错（§12 ⑤） |
| **为改结构重建仓库，历史全丢** | 以为 `mv` 会让 git 认不出重命名 | 同分区 `mv` 即可，git 按相似度识别 rename，`git log --follow` 可追（§12 ⑤） |
| **"还没插进去，波纹就先泛起来了"** | 动效起点写成"镜头起点 + 固定偏移"，与真正的事件帧无关 | 起算点绑**事件完成帧**（物件到位那一帧），之前直接不渲染（§5 5.4） |
| **扩散动效扩散到画面边缘就停住** | 终点半径按目测给，没按画幅算 | 半径 ≥ **屏幕半对角线**（1080p 约 1100px），配 `easeOut` + 线宽/透明度衰减（§5 5.4） |

## 10. 迁移到新视频：改什么、留什么

要做一支**全新题材/新画幅**的视频时，按这张表判断工作量。

### 必须重做
| 项 | 原因 |
|---|---|
| 时间轴 | 节奏、镜头数、总时长全变 |
| 概念帧（每镜） | 内容完全不同 |
| 素材层 | 新题材新画面 |
| 覆盖层内容 | 文案与图表全新 |
| BGM | 时长与情绪要匹配 |

### 改参数即可
| 项 | 怎么改 |
|---|---|
| 画幅/分辨率 | 改覆盖层容器尺寸 + 素材输出尺寸，**两处必须一致** |
| 帧率 | 改合成脚本参数 + 时间轴换算，**素材层要重生成**（帧率不同不能混） |
| BPM / 每拍时长 | 改时间轴基准值，全片时长随之变化，音轨要重新裁 |
| 镜头数 | 增删时间轴条目，注意总拍数守恒 |

### 完全不用动
| 项 | 说明 |
|---|---|
| 七条硬规则 | 与题材无关 |
| 三道质检闸门 | 判据通用（阈值可按平台微调） |
| 分层架构 | 素材/覆盖层/音轨的职责划分 |
| 构建与合成脚本 | 逻辑通用，路径配置化即可 |
| 开源技能库 | 文案、动效、构图参考可复用 |

**判断口诀**：**内容和节奏要重做，工具和判据可复用。**

## 12. 工作流自维护

这套流程本身要持续进化，否则下一次还会踩同样的坑。机制分三层：

**① 经验沉淀**：每支片做完，把「症状 → 根因 → 规则」补进第 8 节踩坑速查表；把新方法补进对应章节。只写**可复用的通用结论**，不写某支片的一次性数据（镜号、具体秒数）。

**② 自动同步**：仓库根有定时任务，定期读最近的记忆日志，检查经验是否已进文档，然后提交推送。调度**只能用时间触发**（没有"打开软件/会话开始"这类事件钩子），且 rrule 解析器不支持多值 `BYHOUR`——想一天跑几次就用 `INTERVAL` 近似，别指望"开工时自动跑"。

```bash
python reference/scripts/sync_workflow.py              # 提交并推送（无改动时安静退出）
python reference/scripts/sync_workflow.py --dry-run    # 只看会提交什么
python reference/scripts/sync_workflow.py -m "docs: …" # 指定提交信息
```

脚本自身按 `__file__` 上溯两级定位仓库根，**与从哪个目录调用无关**——目录结构一改（如把 `scripts/` 收进 `reference/`），唯一要改的就是这行调用路径。

脚本做了三件防呆：
- **无改动安静退出**——否则定时任务每天报错，很快就没人看了
- **推送双通道**——先试 `git push`（2 次），不通自动退 GitHub API
- **大文件拦截**——单文件超 95MB 直接拦下，不然 GitHub 会拒收整次推送

**推送通道（结论会随环境变，别记死端口）**：本机没有直出网络，一切走本地透明代理。**代理端口是会变的**（`63543`、`60217`、`7890` 都出现过），所以不要把"某个端口能通/不通"当成长期结论——上一轮写下的"`git push` 必然失败"很容易在环境换了之后变成自我实现的错误前提。

正确的做法是**先探通道，再选路径**：`git push` 报 `CONNECT tunnel failed, response 502` 就换一个代理端口重试（Clash 常用 `127.0.0.1:7890`），通了就走 `git push`——提交历史保持线性，最干净。**只有在所有可用端口都被拦时**才退 GitHub API，且必须按下面的 SHA 约束复刻提交。

**API 推送的关键约束：不能让 SHA 分叉。**
直接"传文件 → 造新 commit → 更新 ref"会得到内容相同但 SHA 不同的提交，之后本地与远程
不再是同一条链，`git push` 会被判非快进而永久失败，本地还缺远程那个 commit 对象。
解法是**逐字节复刻本地提交**——tree、parents、author/committer（含时间戳与时区）、
message（含末尾换行）全部照抄，GitHub 算出的 SHA 才会与本地相同。
`_gh_api.py` 每造一个 commit 都用 `git rev-parse <sha>^{tree}` 校验，不一致立即中止。

⚠️ **本仓库有中文文件名**：git 默认 `core.quotepath=true`，会把非 ASCII 路径输出成八进制转义（`\350\247\206…`）。任何解析 `git` 输出的脚本拿这种路径去 `cat-file` 都会失败，且报错信息完全指不到真正原因。所有 `git` 调用统一加 `-c core.quotepath=false`。

边界：`out/`（成片/底板/帧，数百 MB）、`node_modules/`、以及 `*.mp4`（成片与投稿副本，动辄上百 MB）在 `.gitignore` 里，永不入库。视频文件只留在本地与平台，仓库里放的是**能重建它的代码与参数**。

**③ 磁盘清理：按可重建性分，不按大小分**

一支片做完，`out/` 往往涨到几百 MB。删之前先问"这个删了还能重建吗、要多久、要不要 GPU"：

| 类别 | 处理 | 典型项 |
|---|---|---|
| **必须留** | 不可再生 / 重建要 GPU | AI 生成素材（重跑结果不可复现）、原始音源与参考素材、成片与封面、分镜与文案 |
| **可删** | 脚本几分钟能重建，不需要 GPU | 质检截图、底板分段与中间拼接、中间音轨、探针图、运行日志 |

**判据**：留下的项要能在 `README` 里逐条写出"保留理由 + 重建命令"。写不出重建命令的，说明它其实不可再生，别删。

**④ 文档与技能：消灭双副本**

同一份 SOP 只要存在两个物理位置，就一定会分叉——改了一份、忘了另一份，下次开工读到的规则和上次踩坑总结出来的规则不一致。

| 位置 | 角色 |
|---|---|
| 用户级 `~/.workbuddy-ai/skills/WorkBuddy_Video_Workflow/SKILL.md` | **主副本**，Agent 实际加载的 |
| 仓库 `skills/WorkBuddy_Skills/WorkBuddy_Video_Workflow/SKILL.md` | 手工副本，供团队/换机时取用 |

规则：**改完用户级版本，立刻覆盖仓库副本**；推送前 `diff` 一次两边，确认无差异再提交。反过来（先改仓库副本）同样要回灌，否则主副本才是滞后的那个。

判断哪个更新：看内容里最近一条经验的时间点，不要看文件 mtime——`git checkout`、复制粘贴都会把 mtime 刷成"现在"。

**⑤ 仓库结构：技能按平台分，其余按用途分**

```
skills/<平台>_Skills/<技能名>/   ← 技能本体（WorkBuddy / Codex / Qoder / Zcode …）
docs/                           ← 方法论（通用流程、演进记录、复盘）
films/<片名>/                    ← 各片交付（分镜 / 文案 / 质检报告 / out）
reference/                      ← 参考实现与共享脚本（含 sync_workflow.py）
```

- **新增平台 = 建一个 `<平台>_Skills/` 目录 + README 占位**（写清加载路径），技能本体不用改——流程与工具无关，换平台只是换"谁来读这份 SOP"。
- **迁移大目录用同分区 `mv`，秒级**；git 在 diff 时按内容相似度自动识别 rename（一次迁移上百个文件全部识别为 rename），`git log --follow` 照样能追历史。**不需要** `git mv` 逐个搬，更**不要**为改结构重建仓库——重建丢历史，且等于全量重传。
- **换层级后立刻验证忽略规则**：`.gitignore` 写 `out/` 而不是 `/out/`。不带前导斜杠的规则匹配**任意深度**的同名目录，带斜杠只匹配仓库根那一层——`out/` 一挪进 `films/x/out/` 就漏，几百 MB 产物被提交，推送被 GitHub 整次拒收。验证用 `git check-ignore -v <路径>`，别靠肉眼。
- **迁移后全仓 grep 旧目录名**（文档、脚本、技能 references、分镜里的路径），一次改完。漏一处不会报错，只会在某天静默读写错目录。

## 附录 B：项目特定经验

以下是做具体片子时踩到的坑，**不具备普适性**，仅供同类题材参考：

- 用"眼皮开合"类比腺苷积累时，慢放素材要让水滴落点精确等于眼皮合上那一拍——靠规则 5（`lt /= K`）实现
- 深色背景 + 发光文字时，`.ov-scrim` 压暗渐变会让下半屏"很黑"，这是设计意图不是 bug
- 同一 AI 模型连续生成相邻镜头时，容易产生相似构图，提示词里要显式写"区别于前一镜"的视觉特征

### 陈桥兵变片复盘（历史题材 · 21 幕 / 213s / 1920×1080）

**成本结构**：内容结构本身只改了两轮，**七轮返工里有五轮花在"画面做糙了"**——人物像火柴人、字幕压画面、城门画错、龙椅不像龙椅。每轮都要重渲 5112 帧。结论：**第一版就把人物、字幕安全区、考据做对，比任何后期优化都省时间。**

升格为正文规则的四条（见 §5.3 / §5.5 / §7.2 / §8.1）：字幕 y<780、人物三段式手臂、BGM 延长剪辑、抖音双封面规格。

只对本片有用的：

| 经验 | 说明 |
|---|---|
| **开头用数字对撞** | 「53」砸屏 → 14 块帝牌连环倒 → 王冠坠落 → 黄袍闪现，四拍撑住前 3 秒；纯风景起幅抓不住人 |
| **地图必须核对地理** | 高平在开封以北、黄河横在两者之间、太原西北、幽州东北。画错方向一眼假，比画得糙更致命 |
| **进度条要在剧情点收口** | 「条件成熟度」卡在登基那一刻到 100% 并淡出；如果一直挂到片尾，观众会觉得"该讲的没讲完" |
| **措施类内容做画布层次** | 「入城约法 / 优待柴氏 / 旧臣留用」横向大幅铺开、压暗覆盖前朝画面，比三张卡片并排更能表达"这是更高明的做法" |
| **人物密集场景要分前后排** | 万岁场景 16 人：后排压暗缩小、前排亮且大；环绕场景按 `sin(角度)` 分两批绘制，前排遮住主角才符合透视 |

### 第二轮改进的实测数据（2026-10）

拿这套流程回头改已完成的片子，改前改后对比，可作为"改动幅度该多大"的参照：

| 镜 | 问题 | 改动 | 静止占比 |
|---|---|---|---|
| s8 | 标题压浅色液体柱，几乎不可读 | 数据组上移 130px、文字下移 64px、底衬 alpha 0.82→0.95、标题描边 1.6px | 50.5% → 42.7% |
| s9 | "23:00"压亮粉窗帘发糊 | `paint-order:stroke` 描边 8px | 19.1% → 18.3% |
| s7/s11 | 标题压人脸 | 全局 `.h1` 描边 0.7→1.1px | 32.7% → 31.9% |
| s6 | 17.1s，下半屏死黑，静止 73.7% | 光点加 4 段尾迹 + 半径 8→11 + 过节点脉冲 + 下半屏粒子流 | 73.7% → 61.8% |
| s5 | 18.2s，光点只跑一遍就静止 13 秒 | HPA 传递光点改为持续循环（2.6s 一圈） | 57.1% → 51.1%，最长静止 2.29→0.83s |
| s13 | 后半段只有峰值点在闪 | 信号光点沿曲线流动 + 高亮带呼吸 | 38.4% → 38.4%（观感改善，判据没动） |

**两条结论**：
1. 可读性问题的修复**不影响**判据（s9/s7 只动 1 个百分点），但它是观众最先感知到的东西——不能因为"数据没变化"就认为白改。
2. s6 加到这么多动效，判据也只从 73.7% 降到 61.8%。**17 秒的镜头靠覆盖层救不回来**，根因在长度，不在动效多少。这就是第 1 步"无 >12s 长镜"那条规则的来源。
