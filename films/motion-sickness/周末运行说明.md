## 四、周一要做的三个决定

### 1. s1 选哪一版

三版对比：

| 版本 | 症状 |
|---|---|
| `s1_v1` | 颠簸重（提示词里写了 `camera swaying with the suspension`）、视角漂成前方路面 |
| `s1_v2` | 颠簸修好、视角回到侧窗，但窗外景物**只平移不转角度**，像世界在传送带上 |
| `s1_e8` | 8 步三相位采样，理论上能减轻 Lightning 的"慢动作"惰性 |

**判断标准**（按用户反馈）：
- 拐弯时窗外景物**通过角度要变**（护栏后退角在变、远山从一侧转到另一侧），不是固定一个角度
- 不能有"车要飞出悬崖"的感觉——路面和护栏要贴近车窗下部
- 窗框/座椅剪影相对镜头不能晃

### 2. s2 / s4 是否接受重做版

这两镜原来用旧提示词生成（含 `camera sways with the car`），已用修正后的提示词重做。对比看有无颠簸差异。

### 3. 如果 8 步也不行

降级阶梯还剩两档：
- **换模型**：本地有 `D:/AI/WanGP/models/hunyuan_video_1.5_i2v_720_quanto_bf16_int8.safetensors`（8.5GB），需要另搭一套 ComfyUI 工作流（节点不同），无人值守不适合盲搭，建议当面做
- **改分镜**：s1 不演转弯，只做匀速侧向掠过（护栏本身是弯的就能看出在弯道上），把"拐弯"交给文案承担

## 五、如果任务全死了怎么重启

```bash
cd "reference"
```

## 六、队列的四条保证

1. **绝不抢占别人的算力**：每镜提交前过 `gpu_gate`，检查外部生成进程 / ComfyUI 队列 / GPU 利用率 / 空闲显存。**从不调用 `/interrupt`、从不清空队列**——别的软件排的活原样跑完。
2. **任务不挂死**：单镜硬上限（4 步 100 分钟 / 8 步 160 分钟）。超时先查磁盘（可能只是慢），磁盘也没有就记失败、跳过、继续下一镜。
3. **不重复提交**：超时后**不重试**（任务可能还在 ComfyUI 里跑，重试等于同一活干两遍）。
4. **同名不串片**：磁盘兜底按「文件名前缀 + 提交时间」双重过滤——共享输出目录里躺着上一支片的 s5/s7/s12/s13/s14，不按时间过滤会静默拿错素材。
